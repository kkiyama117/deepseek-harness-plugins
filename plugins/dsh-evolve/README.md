# DSH Evolve

ツールの失敗と同一呼び出しの反復を観測してスキルの改善候補を作り、出力テストで比較し、人間が承認してから適用する独自DSHプラグインです。モデル自身による適用や、既存のスキル・設定ファイルの書き換えは行いません。

## 対応範囲

対象DSHは `0.2.1-rc.3`、Node.jsは24.9以上です。Webプロファイルが提供する `agentPresets` サービスが必要です。独自のheadless構成では、既存のregistryがない場合だけ `@deepseek-ai/dsh-agent-preset-registry` のHost行を追加してください。初版では設定で宣言した `evolve-` 接頭辞のスキルだけを管理します。ツールの再試行ラッパー、成功を装う代替応答、生成物を任意コードとして実行する機構は含みません。

[lispking/dsh-auto-evolve](https://github.com/lispking/dsh-auto-evolve)の「観測→提案→比較→適用」という構成を参考にした独自実装です。上流ソースは複製していません。設計上の判断と確認条件は[設計](./DESIGN.md)にあります。アイコンはこのパッケージ用のオリジナルSVG、コードとアイコンはMITライセンスです。

## 利用

bundleの初期設定は `observe` です。観測記録を保存しますが、LLM呼び出しはしません。実環境へのインストールは自動で行わず、別途明示的に実施します。

```sh
dsh plugin --profile web add /absolute/path/to/dsh-evolve
```

`propose` にすると、失敗の閾値と実行間隔を満たしたときに候補の生成・検証までを行います。管理対象、固定モデル、正の制限値、期待する出力を事前に設定する必要があります。設定の不備は起動時に拒否されます。

### 設定例

以下は利用者のpatchによる `local-evolve` 行の設定例です。行のconfigは全置換です。制限値とテストは例であり、運用上の予算や業務の合格条件として自動採用するものではありません。

```yaml
- id: local-evolve
  config:
    mode: propose
    locale: ja
    route:
      provider: ollama-cloud
      model: deepseek-v4.1-flash
    dailyRequestLimit: 20
    request:
      maxOutputTokens: 1000
      maxInputBytes: 64000
      maxOutputBytes: 64000
      timeoutMs: 30000
    inspectionMaxBytes: 16384
    assets:
      - name: evolve-evidence-response
        description: 証拠がない場合は推測せず、検証状況をJSONで回答する。
        tests:
          - id: missing-evidence
            prompt: 参照資料がありません。検証状況だけをJSONで回答してください。
            jsonEquals:
              status: needs_review
```

`initialContent` を指定すると、人間が設定した初期の本文として登録されます。既存の保存版は設定の初期値で上書きしません。同名の外部スキルがある場合は起動・適用を拒否します。

出力の検査は `equals`（完全一致）、`contains`、`notContains`、`jsonEquals` が使えます。JSONは応答全体をparseし、余計な文章やフィールドを許しません。期待値は提案モデルに渡さず、モデルがテストを変更する手段もありません。

### 人間のコマンド

- `/evolve status` — 状態、適用中の版、日次枠、保存障害の確認。
- `/evolve candidates` — 保存中の候補ID・digest・検証状態。
- `/evolve show <id>` — 候補の本文と検証結果。
- `/evolve cycle` — 候補の生成と検証を一回実行。
- `/evolve approve <id> <digest>` — 表示された候補を承認。
- `/evolve reject <id> <digest>` — 候補を却下して履歴に記録。
- `/evolve rollback <asset> <revision>` — 指定した現行版から親版へ復元。
- `/evolve history` — 直近の人間の操作履歴。

設定した初期本文の版を超えて過去へ復元する操作は拒否し、初期スキルを誤って非公開にしません。候補や履歴の上限で変更が止まった場合は、保存データを確認したうえで該当する `storage.*` の設定を引き上げる必要があります。アーカイブ機能はありません。

これらはDSHの人間専用コマンド機構で処理し、モデルへ送信しません。エージェント用のツールは読取専用の `evolve_inspect` 一つだけです。適用ツールは登録しません。信頼済みHostプラグインや管理者が直接コード・ストレージを変更する場合の防御は対象外です。

## 評価と復元

各テストを、変更前と候補の本文で一回ずつ、新規Sessionにより実行します。会話履歴を継承せず、専用プリセットと実行直前のguardで全ツールを拒否します。試行の完了は記録された `turn/end` と回答から確認します。待機状態や、エラー数の減少だけでは合格にしません。

承認待ちになるのは、候補が全テストに合格し、少なくとも一つの変更前の不合格を改善した場合だけです。入力・応答の上限、期限、モデル経路、出力トークン上限の違反やツール要求は検証失敗です。中立の候補も適用しません。候補IDとdigestには本文、説明、基準版、評価設定を紐づけ、テスト・モデル・基準版が変われば古い承認を拒否します。

本文の各版と親版を保存し、適用中の版を指すポインタをcommitしてからスキルを公開します。復元は保存済みの親版を使い、本文を再生成しません。初回追加の親版がなければ公開を解除します。再読み込み時にも保存済みの適用ポインタを使います。

## 制限と保存障害

`dailyRequestLimit` はUTC日ごとの実リクエスト数です。各試行は一回だけ呼び出し、追加のリクエストや自動再試行は拒否します。実際に呼び出す前に枠を永続化し、失敗・中断でも払い戻しません。プラグインの再読み込みで枠は戻りません。これは金額や入力を含む総トークン数の上限ではありません。

入力は構築された完全なリクエストのUTF-8バイト数、応答は正規化されたchunkをJSON化した累積バイト数を制限します。後者は本文deltaと完成blockを両方数えるため、表示本文より大きくなります。`timeoutMs` は処理を中断し、終了処理を待ってから次のサイクルを許可します。提供方が中断を無視して終了しない場合は後始末を待つため、そのプロセスの強制終了を保証するものではありません。

観測記録は `observation.maxRecords` の直近分だけ保持します。生の引数やツール結果・エラーメッセージを保存・提案送信せず、ツール名とエラーコードなどの記録に限定します。反復検出の引数は一時的なhashだけにします。

候補・版・履歴・日次枠は `storageDomain` の `local_evolve` 領域の一つのレコードに保存します。`storage.maxCandidates`、`maxRevisions`、`maxHistory`、`maxStateBytes` を超える場合は書き込みを拒否し、履歴を削除して続行しません。保存障害後は新たな提案・変更を停止し、公開スキルも取得不能にします。最後に確認できた状態はstatusで診断できますが、障害後の正しい保存状態と同一視しないでください。

## 確認と開発

```sh
pnpm install --ignore-workspace --ignore-scripts --config.auto-install-peers=false
DSH_HOST_ROOT=/absolute/path/to/deepseek-harness node --test tests/*.test.mjs
node bin/check.mjs
```

テストは模擬LLMを使います。実際のheadlessプロファイルをLoaderで構成し、候補生成、比較、人間コマンド、実スキルの読込、正確な復元、再読み込みによる版と予算の維持、破棄後の登録解除を確認します。ストレージ障害、日次制限、経路変更、出力の誤りなどは決定論的な試験で確認します。実モデルによる改善効果や、Web画面での表示確認とは別の証拠です。

### Model Experience

モデルには読取専用ツール `evolve_inspect` のschemaが追加されます。現行Hostのヒューリスティックによるschema単独の初回要求の推定は0→90トークンです。親会話全体や外部提供方の実測値ではありません。スキル本文は承認後に一覧へ現れ、通常のskill機構による読込時にだけ渡されます。候補の生成・評価では一回の提案呼び出しとテスト数の二倍の呼び出しを使います。人間コマンドと保存状態だけでは親モデルの会話本文を変更しません。公開スキルの変更はカタログとプロンプトのprefixを変え、KVキャッシュの再利用に影響し得ます。

## Known Limitations and Deferred Work

- テキスト出力のテストで、ツールを使う業務タスク全体の正しさは保証しません。汎用OSサンドボックスではなく、LLMの通信は行います。
- 一組の比較にはモデルの揺らぎが含まれます。統計的な能力向上や、未知の入力への一般化は保証しません。候補を読んでから承認してください。
- モデル経路と記録上のidentityを確認しますが、外部提供方の内部のモデル重みまでは証明できません。他の信頼済みHostプラグインによる改変は権限分離の対象外です。
- 候補・履歴のアーカイブや自動的なデータ移行は実装していません。上限到達時は停止します。検証に失敗した候補も記録を保持します。
- この版の実環境への導入と実LLM試行、Web上のアイコン・表示確認は未実施です。
