# 反映と結果報告

PR、merge、リリース、利用環境への反映、Issueの完了判断を行う前に読む。入力は検証済みの成果物、検証結果、当初の完了条件と許可された反映先。

## 反映する

1. PRに対象Issue、変更内容、実施した検証、未確認事項を記載する。投稿操作の前に [GitHubでの操作](../references/project-setup.md#githubでの操作)を読む。
2. merge・リリース・利用環境への反映は、対象プロジェクトの権限と手順に従う。PR作成、merge、稼働環境への反映を同一視しない。
3. Issueの完了条件に配備・実利用確認が含まれるなら、PRには `Refs #N` を使い、merge時の自動closeを避ける。mergeで全条件を満たす場合だけ `Closes #N` を使う。
4. 必要な反映権限がなければ、成果物と具体的な残作業を報告し、実装済みでもIssueは未完了のままにする。

## 結果と完了を記録する

Issueコメントへ [結果報告の項目](../references/project-setup.md#結果報告)を記録し、条件を満たしたものだけ完了にする。見送り・重複によるcloseは理由と関連先を示し、実装完了とは区別する。機能の検証に失敗した場合はopenのままにする。

報告後も同じ不具合が確認されたら、既存Issueの再開または関連Issueで追跡する。旧結果報告は残し、新しい証拠・対象版・確認日を追記して完了条件を再評価する。別の原因や独立した完了条件を持つ問題は、新しいIssueから関連付ける。

## この工程の結果と次の作業

確認した反映先と、その証拠、完了・未完了の条件を返す。PRを作れたことだけで元の依頼を完了にしない。

最後に [振り返りと改善](06-improve.md)を確認する。新しい不具合なら [課題整理](02-intake.md)、既存指摘の修正なら [実装・検証](04-implement-verify.md)へ戻り、必要な範囲だけ進める。
