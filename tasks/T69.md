## T69. dispatch.py review: only whole runs count as having run

Issue: #95.

Tier: R1

Needs: T68 (merged).

Spec: the Rules and Tests below are the full spec. Read-only background: `/data/softwares/kstack/docs/contracts/acceptance.md` section 5 at kstack main 905bbd1, which says: "A run is **whole** when its wrapper exit is 0, its answer has a `TOTAL` line whose number equals the count of finding lines, and the answer has no `STOPPED` line." and "Records that are `optional` or not whole do not count as having run. That holds for the cases below, for round numbers, and for `covers_from`, which is the state of the latest whole `round` or `fixcheck`. Findings count from every required record." The checker's test is `run_is_whole` in `/data/softwares/kstack/bin/kstack-accept` (exit 0, no `STOPPED`, a `TOTAL`, and that number equal to the count of finding lines; when an answer has several `TOTAL` lines, the last one counts). The interim rule of T67 stays: a run that exits 0 without being whole is recorded as `optional` only when its answer has no finding line, and otherwise keeps its kind. This card does not change that rule, which decides the kind recorded for a run that has just finished; it changes which earlier records count as having run, so the kind derived for a later run can change (as `test_review_cut_off_round_does_not_count` shows). kstack harness-architect's ruling of 2026-11-17 for this card (to go into section 5 in a later kstack PR) reads section 5 as two statements: "has it run" counts only whole, non-optional `round`/`fixcheck` records (derived kind, round numbers, `covers_from`); "what was found" counts findings from every `round`/`fixcheck` record, whole or not. A supplement cannot complete a cut-off run, because the checker passes over that run's `UNREAD`/`DENIED` lines once a whole rerun stands in for it. Code to change: `parse_answer` and the history in `_review` in `bin/dispatch.py`; tests in `bin/test_dispatch.py`.

Files: `bin/dispatch.py`, `bin/test_dispatch.py`.

### Rules

1. `parse_answer(path)` keeps its signature and return value `(findings, complete)`, and its fence handling. A `TOTAL` line is still a line matching `^TOTAL\s+\d+\s*$`, and a `STOPPED` line one matching `^STOPPED\b`. `complete` is now true only when the answer has at least one `TOTAL` line outside fences, the number on the last such line equals `len(findings)`, and no `STOPPED` line is outside fences. Everything that uses `complete` today (the incomplete-answer rule) uses this stricter value unchanged.
2. A review record is whole when its kind is `round` or `fixcheck`, its `exit` is the integer 0 (as kstack-accept's `run_is_whole` requires; a record written by this dispatcher with a nonzero exit is `optional` anyway), and `parse_answer(record['answer'])` gives `complete` true. Wholeness is decided while the history is built, before `seq` and before the `review --kind {kind} needs an earlier round or fixcheck` refusal; an answer file of a `round` or `fixcheck` record that cannot be read raises the existing `DispatchError(f'bad review record {path}: cannot read {answer}')` there, with `path` the record file and `answer` the answer path, so it wins over that refusal.
3. In `_review`, build two lists while reading the records, both in `seq` order: `history`, the whole `round` and `fixcheck` records, and `required`, every `round` and `fixcheck` record whether whole or not (never `optional` or `supplement`). `history` answers "has it run"; `required` answers "what was found". Everything that reads `history` today reads the whole-only list unchanged, except where this rule says `required`:
   1. `latest` = the last record of `history`: the anchor of `covers_from` and of the fix-check brief (its covered run and covered findings), and the refusal `review --kind fixcheck needs an earlier round or fixcheck`. A record that is not whole is never an anchor.
   2. The derived kind and the round numbering read `history` (`rounds`, `latest_round`, the first `round` 1 record, and "no record has `round` 2": a cut-off round 2 does not count, so the next run is round 2 again), with one exception: the round-2 case's candidates ("some `fixcheck` record whose `seq` is greater than the `seq` of the first `round` 1 record has a fixed high and a `state` different from `state`") come from `required`, so a cut-off fix check's fixed high still leads to round 2, as kstack-accept's `REVIEW_ROUND2_MISSING` counts it.
   3. Supplement. `last_required` = the last record of `required`. `--kind supplement` with no record in `required` keeps the existing refusal `review --kind supplement needs an earlier round or fixcheck`. When `last_required` is not whole, raise `DispatchError(f'run {seq} was cut off; rerun it (the derived kind gives the same kind, and the same covers_from for a fix check); its UNREAD/DENIED lines are passed over once a whole run stands in, and a supplement then covers the whole rerun if that one has such lines')` with `seq` = `last_required['seq']`; no worker runs. Otherwise `covers = last_required['seq']`. A supplement never points at an older whole run.
4. The dispose check is unchanged: it still checks the findings of every record that is not `optional`, whole or not.
