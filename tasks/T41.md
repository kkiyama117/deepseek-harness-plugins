### Rules

1. **Timeout.** Add the option `--probe-timeout SECONDS`, default `600.0` (a float), parsed by a new `type` function `probe_timeout_seconds` (built like `retry_seconds`) that accepts a finite float greater than 0 and otherwise raises `argparse.ArgumentTypeError('must be a finite number of seconds, greater than 0')`. `run_child` starts every child with `subprocess.Popen(argv, cwd=..., env=..., stdout=PIPE, stderr=PIPE, start_new_session=True)` (an `OSError` from `Popen` is T40's child that cannot start: exit code `None`, `str(error)` in `.err`, empty `.out`) plus `stdin=subprocess.DEVNULL` and `communicate(timeout=<probe timeout>)` for a config check, or `stdin=subprocess.PIPE` and `communicate(input=<PROBE_TASK bytes>, timeout=<probe timeout>)` for a model probe. On `subprocess.TimeoutExpired`, it kills the whole process group with `os.killpg(proc.pid, signal.SIGKILL)` (ignoring `ProcessLookupError`), collects the output with `communicate(timeout=10)` (if that also times out, the output is empty), appends `live-apply: timed out after <seconds> seconds` (UTF-8, no newline; `<seconds>` as `str()` of the option's float) to the collected stderr, and returns exit code `None` with that output, so the check fails and its `.out`/`.err` hold what the child left plus that line. The child environment (T40's parent environment plus `DSH_HOME` and `DSH_CLI`) also drops `RUN_WORKER_EVENTS`, so `run-worker.sh` never writes its event stream into a probe directory. If `communicate` raises `KeyboardInterrupt`, `run_child` kills the process group the same way, waits for it, and re-raises; that attempt writes no `.out`/`.err` and gets no `checks` entry.

2. **Interrupt.** `KeyboardInterrupt` (SIGINT) is handled in two places:
   - In `Apply.run`, around `steps()` (a SIGINT anywhere inside it, including the retry wait, `os.replace`, record writes, and `abort`; a second SIGINT during this handling is out of scope), in this order: if `self.replaced` is true (the target holds the new bytes), restore it as step 8 does and print `LIVE_APPLY_INTERRUPTED: <T> was restored` to stderr, or, when that restore raises `LiveApplyError`, `LIVE_APPLY_INTERRUPTED: restore <T> from <RECORD>/backup.yml by hand: <error.error>` (`<RECORD>` is `str(RECORD)`) (`LIVE_APPLY_INTERRUPTED: remove <T> by hand: <error.error>` when the old target was absent). Else, if `self.ever_replaced` is true, print `LIVE_APPLY_INTERRUPTED: <T> was already restored`. Else remove the temporary file if it exists (ignoring an `OSError`) and print `LIVE_APPLY_INTERRUPTED: the target was not changed`. Then the status is `interrupted` and the exit code is 130; the summary is printed as for any other status.
   - In `main`, around building `Apply` (the usage rules): print `LIVE_APPLY_INTERRUPTED: the target was not changed` to stderr and exit 130 with nothing on stdout. This amends T40's "every exit except a usage error prints one JSON object": a SIGINT during the usage rules prints none either.

   The summary's `status` can now also be `interrupted`; the code keeps no list of statuses, and `tasks/T40.md` is not edited.

3. **Symlinks.** In `check_usage`, right after the route check and before the `headless` check, add these usage rules in this order; each prints its message to stderr and exits 2 with nothing on stdout:
   - `os.path.islink(T)`: `LIVE_APPLY_USAGE: target is a symlink: <T>`.
   - For `profile-patch`, `os.path.islink(H / 'profiles')`: `LIVE_APPLY_USAGE: profiles directory is a symlink: <H / 'profiles'>`.
   - For `profile-patch`, `os.path.islink(T.parent)`: `LIVE_APPLY_USAGE: profile directory is a symlink: <T.parent>`.

   A symlink in `H` itself or above it is allowed.

4. **File modes.**
   - In step 2, when the old target exists, read its mode with `stat.S_IMODE(os.stat(T).st_mode)` together with its bytes (an `OSError` is `read target`). `replace_target` sets the temporary file's mode with `os.chmod` to that old mode before `os.replace`, for the write of step 6 and for every restore; a target that was absent is written with mode `0o600`, whatever the umask. An `OSError` from that `chmod` is the caller's operation (`write target` in step 6, `restore target` in a restore).
   - After `mkdir` in step 4, `os.chmod` the record directory to `0o700`, whether the script created it or found it empty. After writing any file in it (`write_record` and `summary.json`), `os.chmod` that file to `0o600`. An `OSError` from these `chmod` calls is `write record` (or, for `summary.json`, the existing `write summary` exception).

5. **Usage-step errors.** In `main`, an `OSError` raised while building `Apply` (the usage rules read the file system) prints `live-apply: check usage: <error>` to stderr and exits 2 with nothing on stdout. Nothing has been written at that point.

6. **Record writes during a check.** In `config_check` and `probe_attempt`, append the attempt's `checks` entry before calling `write_attempt` (in `probe_attempt`, `ok` is decided first, including the `os.listdir` test); when `write_attempt` then raises, the entry stays and the run follows T40's "Other errors" rule (`write record`, exit 1). In `probe_attempt`, the probe directory is removed even when something raises after `mkdtemp`: a `try` that starts right after `mkdtemp` has a `finally` that runs `shutil.rmtree`; when any exception (a `LiveApplyError` or a `KeyboardInterrupt`) is already propagating, an `OSError` from that removal is ignored, and otherwise it is `probe directory` as in T40.

7. **One restore.** `replace_target` with `write target` sets both `self.replaced` and a new flag `self.ever_replaced`; `restore()` sets `self.replaced = False` once it succeeds. So a later `LiveApplyError` (for example during the `rollback` phase) does not restore the target again, and `abort` restores only while `self.replaced` is true.

8. **Service warning after an error.** When the run ends with status `error` or `interrupted` and `self.ever_replaced` is true, print the `LIVE_APPLY_CHECK_SERVICE: <service> may have restarted while the new patch was in place` lines of T40's step 9 for every reached service, after the other stderr lines that `run` prints and before `emit` (so before any `live-apply: write summary:` line). This replaces T40's sentence that a failed restore prints no such lines: after a failed restore the new patch may still be in place, so they are printed.

### Tests

Keep every T40 test unchanged. Add these to `bin/test-live-apply.py`, with the same fakes, extended as follows:

- The shared helper that runs the script gets one new named parameter, `umask`, passed to `subprocess.run(..., umask=...)` and never turned into a script option; new environment variables (`$FAKE_PID`, `$FAKE_LOCK`, `$FAKE_DSH_LOCK`, `TMPDIR`) go through its existing `env` parameter. T40 tests keep calling it as before.
- Fake run-worker words: `hang` starts a grandchild `[sys.executable, '-c', 'import time; time.sleep(60)']` with `subprocess.Popen`, writes the grandchild's pid to the file named by `$FAKE_PID`, then sleeps 60 seconds; `interrupt` sends `SIGINT` to its parent (`os.kill(os.getppid(), signal.SIGINT)`), then sleeps 5 seconds and exits 1; `lock` changes the mode of each directory in `$FAKE_LOCK` (split on `os.pathsep`) to `0o500`, prints `391`, and exits 0.
- Fake run-worker: its JSON log line also records `"runWorkerEvents": os.environ.get('RUN_WORKER_EVENTS')`.
- Fake dsh: when `$FAKE_DSH_LOCK` is set, it changes the mode of that directory to `0o500` before exiting.
- A test that sets a mode on a directory restores `0o700` in a cleanup, so `TemporaryDirectory` can remove it. Every test that relies on a permission error (each row that uses `$FAKE_LOCK`, `$FAKE_DSH_LOCK`, or a `0o000` directory) skips when `os.geteuid() == 0`.
