### Rules

1. **Timeout.** Add the option `--probe-timeout SECONDS`, default `600`, parsed by a `type` function like `retry_seconds` that accepts a finite float greater than 0 and otherwise raises `argparse.ArgumentTypeError('must be a finite number of seconds, greater than 0')`. `run_child` starts every child (config checks and model probes) with `subprocess.Popen(argv, cwd=..., env=..., stdin=..., stdout=PIPE, stderr=PIPE, start_new_session=True)` and waits with `communicate(input=..., timeout=<probe timeout>)`. On `subprocess.TimeoutExpired`, it kills the whole process group with `os.killpg(proc.pid, signal.SIGKILL)` (ignoring `ProcessLookupError`), collects the output with `communicate()`, and returns exit code `None`, so the check fails as a child that cannot start does.

2. **Interrupt.** `KeyboardInterrupt` (SIGINT) is handled in two places:
   - In `Apply.run`, around `steps()`: if the target has been replaced by step 6 and not yet restored, restore it as step 8 does and print `LIVE_APPLY_INTERRUPTED: <T> was restored` to stderr, or, when that restore raises `LiveApplyError`, `LIVE_APPLY_INTERRUPTED: restore <T> from <RECORD>/backup.yml by hand: <error>`. Otherwise print `LIVE_APPLY_INTERRUPTED: the target was not changed`. Then the status is `interrupted` and the exit code is 130; the summary is printed as for any other status.
   - In `main`, around building `Apply` (the usage rules): print `LIVE_APPLY_INTERRUPTED: the target was not changed` to stderr and exit 130 with nothing on stdout.

   Add `interrupted` to the summary's list of statuses.

3. **Symlinks.** Add two usage rules right after T40's rule 3, in this order; each prints its message to stderr and exits 2 with nothing on stdout:
   - `os.path.islink(T)`: `LIVE_APPLY_USAGE: target is a symlink: <T>`.
   - For `profile-patch`, `os.path.islink(T.parent)`: `LIVE_APPLY_USAGE: profile directory is a symlink: <T.parent>`.

   A symlink in `H` itself or above it is allowed.

4. **File modes.**
   - In step 2, when the old target exists, read its mode with `stat.S_IMODE(os.stat(T).st_mode)` together with its bytes (an `OSError` is `read target`). `replace_target` sets the temporary file's mode with `os.chmod` to that old mode before `os.replace`, for the write of step 6 and for every restore; a target that was absent is written with mode `0o600`, whatever the umask.
   - After creating the record directory, `os.chmod` it to `0o700`. After writing any file in it (`write_record` and `summary.json`), `os.chmod` that file to `0o600`. An `OSError` from these `chmod` calls is `write record` (or, for `summary.json`, the existing `write summary` exception).

5. **Usage-step errors.** In `main`, an `OSError` raised while building `Apply` (the usage rules read the file system) prints `live-apply: check usage: <error>` to stderr and exits 2 with nothing on stdout. Nothing has been written at that point.

6. **Record writes during a check.** In `config_check` and `probe_attempt`, append the attempt's `checks` entry before calling `write_attempt`; when `write_attempt` then raises, the entry stays and the run follows T40's "Other errors" rule (`write record`, exit 1). In `probe_attempt`, the probe directory is removed even when `write_attempt` raises: run `shutil.rmtree` in a `finally`, and when another `LiveApplyError` is already propagating, ignore an `OSError` from that removal.

7. **One restore.** After the restore of step 8 succeeds, the target counts as not replaced, so a later `LiveApplyError` (for example during the `rollback` phase) does not restore it again.

8. **Service warning after an error.** When the run ends with status `error` or `interrupted` and the target had been replaced at any point of the run, print the `LIVE_APPLY_CHECK_SERVICE: <service> may have restarted while the new patch was in place` lines of T40's step 9 for every reached service, after the other stderr lines of that exit.
