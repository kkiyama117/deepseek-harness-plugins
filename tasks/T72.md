## T72. dispatch.py and gate.py: no caller GIT_*, byte-safe git, no gate output or untracked symlinks in the reviewer brief

Issue: #66.

Tier: R1s

Needs: T71 (landed on this branch).

Spec: the Rules and Tests below are the full spec. They re-cut the fixes of an older card (closed pull request #69) onto the current code; you do not need that card. A security review found these paths: (1) the reviewer's brief, which goes to an outside provider, carries text that code the worker wrote printed (the gate's output); (2) the dispatcher's `git()` inherits the caller's `GIT_*` variables, so run from a git hook it can touch the caller's repository or index; (3) the gate's package checks inherit them too; (4) `git()` decodes in text mode, which turns a carriage return in a file name into a newline; (5) an untracked symlink is listed for the reviewer to read, so it can point the reviewer at a file outside the worktree. Also the worker's launch must not pass the caller's `GIT_*` on. Code to change: `bin/dispatch.py` (including its module docstring), `bin/test_dispatch.py`, `bin/gate.py`, `bin/test_gate.py`; read all four before you change them.

Files: `bin/dispatch.py`, `bin/test_dispatch.py`, `bin/gate.py`, `bin/test_gate.py`.

### Rules

1. `clean_env(environ=None)` in `bin/dispatch.py` returns a new dict copy of `environ` (or of `os.environ` when it is `None`) without any variable whose name starts with `GIT_`.
2. Every subprocess the dispatcher starts runs with a clean environment: `git()`, the gate run in `run_gate` and in `gate_step`, `work_state` (`kstack-accept state`), and `land`'s `kstack-accept check` each pass `env=clean_env()`. The worker is the one exception to the plain form: `run_worker` builds the environment it hands to the boundary as `clean_env(env if env is not None else os.environ)`, and passes that to `module.child_env(...)`. So the caller's `GIT_*` never reaches the worker, while a `GIT_*` variable that the boundary entry itself sets (the real entries set `GIT_CONFIG_GLOBAL`) still does.
3. `run_worker` passes the brief with `encoding='utf-8', errors='surrogateescape'` (keeping `text=True`), so a diff or file name that is not UTF-8 reaches the worker byte for byte instead of raising.
4. `git()` runs `subprocess.run` without `text=True` and returns a `subprocess.CompletedProcess` with the same `args` and `returncode`, `stdout = os.fsdecode(<stdout bytes>)` and `stderr = <stderr bytes>.decode('utf-8', errors='replace')`. Its `allow_failure` behavior and its `DispatchError` message stay as they are.
5. Gate summary. Add `gate_summary(code, output)`: it returns `f'gate: PASS ({n} checks)'` when `code == 0` and the last line of `output` with `line.strip() != ''` matches `^gate: PASS \(([0-9]+) checks\)$` exactly, with `n` that group as an integer; otherwise `'gate: FAIL'`.
   1. `run_gate` and `gate_step` print the gate's merged output to the lead's stdout right after their `gate exit {code}` line: nothing when the output is empty, else `print(output, end='')` and then one `print()` only when the output does not end with a newline. `gate_step` keeps writing the full output to `gate.log` and prints its `gate.json` line after the output.
   2. Instead of the last 40 lines, both return `(code, gate_summary(code, output))`. When `review` reuses gate.json, its tail is `gate_summary(<gate.json exit>, <gate.log text>)`.
   3. `GATE_BLOCK` becomes: ``The dispatcher ran `python3 bin/gate.py` before you started; it exited {gate_code}. Its result (the output of the checks is not shown to you):\n\n```\n{gate_tail}\n```.`` No other text that the worktree's code printed reaches a brief.
   4. Module docstring: in the sentence about `review` running the gate itself, replace the words `the last lines of its output` (they span a line break after `the`) with `a one-line summary of its result (gate: PASS or gate: FAIL)`; change nothing else there.
6. Untracked symlinks, in `review --main` (worktree mode needs no filter: it already refuses a worktree with untracked files, since T67). The untracked list given to the brief holds only paths that are not symlinks (`os.path.islink` on the absolute path). For each untracked symlink, in `git ls-files` order, print `untracked symlink not shown to the reviewer: <absolute path> -> <target>` on stdout, where `<target>` is the raw `os.readlink` value, or `(unreadable)` when that raises `OSError`. The filter and its stdout lines come before the `no changes in the given paths` check and before the gate runs, so an untracked symlink alone is no change.
7. `bin/gate.py`: add `clean_env()` (a copy of `os.environ` without `GIT_*` names). `check_env(check)` starts from `clean_env()` instead of `os.environ`, then adds each `env` entry that is not already set. `run_in_index_copy`'s `environment` starts from `clean_env()` (then adds the index-copy variables as now), and `main`'s merge-base `run_git` call uses `clean_env()`.
