### Facts from DSH Core (a192fea56c) that the plugin relies on

- A plugin with `inject = ['sessions']` can call `ctx.on('session/event', (session, event) => { ... })`. It is called once for every committed event of every Session in the process, in order. Core's own headless JSON stream and the ACP bridge subscribe this way. `ctx.logger.warn(message)` logs a warning.
- `session.header.id` is the Session id (a string). `session.header.cwd` is the absolute working directory the Session was created in, or absent. `session.header.origin` is `'subagent'` for a subagent's child Session and absent otherwise.
- `session.requestHeader()` returns the request header in force after the latest `request/header` event, or `undefined` before the first one. Its `config` has `provider` (string), `model` (string) and optionally `reasoningEffort` (string). A `request/header` event is appended before a request whose configuration changed, so at `turn/end` the header holds the configuration of the turn's last request.
- Event shapes (`event.type` and `event.data`), in the order the loop appends them:
  - `turn/start`: `{ turn }` opens turn `turn`.
  - `step/start`: `{ turn, step }`, one model call plus the tool executions it requested.
  - `assistant/attempt`: `{ turn, step, stream }`, one model attempt that committed no message (a failed or retried attempt). Its billed usage lives only in `stream`.
  - `assistant/message`: `{ turn, step, message, stream, usage? }`, the step's committed message. `usage` is present when the adapter reported token accounting.
  - `step/end`: `{ turn, step }`. Core appends it in a `finally`, so every `step/start` gets one, even when the step fails or is aborted.
  - `turn/end`: `{ turn, reason }`, also appended in a `finally`, so every `turn/start` gets one. A turn rejected or cancelled before any step has no `step/start`.
  - Other event types (`tool/call`, `tool/result`, `user/message`, `request/header`, and more) carry no usage; ignore them.
- `usage` is a TokenUsage: `{ inputTokens, outputTokens, totalTokens?, cacheReadTokens?, cacheWriteTokens?, reasoningTokens? }`, all numbers. `stream` is an array of records; the usage of an attempt is the `usage` of the LAST record with `record.type === 'chunk' && record.chunk.type === 'usage'`, whose shape is `{ type: 'chunk', time: <number>, chunk: { type: 'usage', usage: <TokenUsage> } }`. Other records (`text-chunks`, `reasoning-chunks`, other chunk types) carry no usage.
- How Core's headless sums one step's attempts (`packages/bundle/headless/src/json-stream.ts`, quoted; the plugin must give the same per-step result):

  ```ts
  function addUsage(state, next) {
    if (next === undefined) return { usage: state.usage, complete: false }
    if (state.usage === undefined) return { usage: next, complete: state.complete }
    const total = state.usage
    const sum = (a, b) => a === undefined || b === undefined ? undefined : a + b
    const totalTokens = sum(total.totalTokens, next.totalTokens)
    const cacheReadTokens = sum(total.cacheReadTokens, next.cacheReadTokens)
    const cacheWriteTokens = sum(total.cacheWriteTokens, next.cacheWriteTokens)
    const reasoningTokens = sum(total.reasoningTokens, next.reasoningTokens)
    return {
      usage: {
        inputTokens: total.inputTokens + next.inputTokens,
        outputTokens: total.outputTokens + next.outputTokens,
        ...totalTokens === undefined ? {} : { totalTokens },
        ...cacheReadTokens === undefined ? {} : { cacheReadTokens },
        ...cacheWriteTokens === undefined ? {} : { cacheWriteTokens },
        ...reasoningTokens === undefined ? {} : { reasoningTokens },
      },
      complete: state.complete,
    }
  }
  // per Session, starting at { usage: undefined, complete: true }:
  // 'assistant/attempt': stepUsage = addUsage(stepUsage, streamUsage(event.data.stream))
  // 'assistant/message': stepUsage = addUsage(stepUsage, event.data.usage ?? streamUsage(event.data.stream))
  // 'step/end': the step's usage is `complete && usage !== undefined ? usage : (none)`; reset stepUsage
  ```

### Facts from kstack's runner (`skills/kiyama-mode/scripts/run-worker-project.mjs`, quoted)

kstack's runner turns headless's `step_end` usages into the `dsh: usage:` line. This plugin adds each step's usage to the turn's totals exactly as it does:

```js
const USAGE_FIELDS = [
  ['input', 'inputTokens'],
  ['output', 'outputTokens'],
  ['cache_read', 'cacheReadTokens'],
  ['cache_write', 'cacheWriteTokens'],
  ['reasoning', 'reasoningTokens'],
];
// dsh sums a step's retried attempts into the one step_end usage, so each step is added once.
function recordStepUsage(event) {
  usageSteps += 1;
  const usage = event.usage;
  if (usage === null || typeof usage !== 'object') { usageIncomplete = true; return; }
  let input = 0; let cacheRead = 0; let cacheWrite = 0; let reported = false;
  for (const [label, key] of USAGE_FIELDS) {
    const value = usage[key];
    if (!Number.isFinite(value) || value < 0) continue;
    reported = true;
    usageTotals.set(label, (usageTotals.get(label) ?? 0) + value);
    if (label === 'input') input = value;
    else if (label === 'cache_read') cacheRead = value;
    else if (label === 'cache_write') cacheWrite = value;
  }
  if (!reported) { usageIncomplete = true; return; }
  if (usageSteps === 1) firstContext = input + cacheRead + cacheWrite;
}
// line: `dsh: usage: steps=N` then `label=total` for each label in USAGE_FIELDS order that usageTotals has, then ` incomplete` when usageIncomplete.
const sanitize = (value) =>
  String(value)
    .replace(/\n/g, '\\n')
    .replace(/\r/g, '\\r')
    .replace(/[\u0000-\u001f\u007f]/g, ' ');
```

### Rules

1. `plugins/dsh-acp-usage/index.mjs` exports `name = 'acp-usage'`, `inject = ['sessions']`, and the functions below. It imports only `node:fs` and `node:path`. JSDoc on each export, in the style of the template.
2. `addAttemptUsage(state, next)` is Core's `addUsage` above, unchanged in behavior. `streamUsage(stream)` returns the usage of the last usage chunk record of `stream`, or `undefined` when there is none or `stream` is not an array.
3. `createListener({ writeLine, appendRecord, warn, now, realpath })` returns the `session/event` listener `(session, event) => undefined`. `writeLine(text)` writes the stderr line, `appendRecord(text)` appends the JSONL line (it is `undefined` when no file is configured), `warn(message)` logs, `now()` returns a `Date`, `realpath(path)` returns a resolved path or throws. It keeps one turn state per Session object in a `WeakMap`:
   1. A Session whose `header.origin === 'subagent'` is ignored entirely (headless's line counts only the root Session's steps, so this line does too).
   2. `turn/start` replaces the Session's state with a fresh one: `turn = event.data.turn`, `steps = 0`, empty totals, `incomplete = false`, no first request input, and step usage `{ usage: undefined, complete: true }`.
   3. Every other event is ignored when the Session has no state (the plugin was loaded in the middle of a turn).
   4. `assistant/attempt` and `assistant/message` update the step usage as in Core's quoted code.
   5. `step/end` adds one step as in kstack's `recordStepUsage`, with the step usage from Core's rule as `event.usage` (`undefined` when the step has none, which marks the turn incomplete). The first request input is kstack's `firstContext`: set only by step 1, and only when step 1 reported a value. Then the step usage is reset.
   6. `turn/end` whose `event.data.turn` equals the state's `turn` builds the record (rule 4), calls `writeLine(usageLine(record))` and then, when `appendRecord` is defined, `appendRecord(JSON.stringify(record) + '\n')`, each exactly once, and deletes the Session's state. A `turn/end` for another turn number is ignored.
   7. Each of the two writes is in its own `try`. When `writeLine` throws, call `warn(\`acp-usage: stderr write failed for session ${id}\`)`; when `appendRecord` throws, call `warn(\`acp-usage: usage file append failed for session ${id}: ${code}\`)` with `code` the error's `code` when it is a string, else its `name`. A failed stderr write does not skip the append. A throwing `warn` is swallowed. The listener never throws: anything else that throws inside it is caught and reported with `warn('acp-usage: usage tracking failed')`, once per throw, with no error text.
4. The record is a plain object whose keys are, in this order:
   - `ts`: `now().toISOString()` at `turn/end`.
   - `session`: `session.header.id`.
   - `cwd`: `realpath(session.header.cwd)`; when `realpath` throws, `session.header.cwd` as given; `''` when `header.cwd` is not a string.
   - `provider`, `model`, `reasoning_effort`: from `session.requestHeader()?.config` at `turn/end`, each the string value of `provider`, `model`, `reasoningEffort`, or `''` when it is missing or not a string. When `requestHeader` is not a function or throws, all three are `''`.
   - `steps`: the turn's step count.
   - `input`, `output`, `cache_read`, `cache_write`, `reasoning`: the turn totals, in this order, each present only when at least one step reported a valid value for it (kstack's rule; a turn with no reported step has none of them).
   - `first_request_input`: present only when set by rule 3.5.
   - `incomplete`: `true`, present only when the turn is incomplete.
   No other key. Never put message text, tool data, or any path other than `cwd` into the record.
5. `usageLine(record)` returns `dsh: usage: session=${sanitize(record.session)} cwd=${sanitize(record.cwd)} steps=${record.steps}`, then ` ${label}=${value}` for each of `input`, `output`, `cache_read`, `cache_write`, `reasoning` that the record has, in that order, then ` incomplete` when `record.incomplete === true`, then `\n`. `sanitize` is kstack's function above (export it). `first_request_input`, `ts`, `provider`, `model` and `reasoning_effort` are not on the line.
6. `resolveConfig(config)` validates the composition row's config and returns `{ file }` with `file` a string or `undefined`:
   - `undefined` or `null` → `{ file: undefined }`.
   - Not a plain object (an array, a string, a number) → throw `Error('acp-usage: config must be an object')`.
   - A key other than `file` → throw `Error(\`acp-usage: unknown config key ${key}\`)` for the first such key.
   - `file` absent → `{ file: undefined }`. `file` present but not a non-empty string, or not absolute by `path.isAbsolute`, or containing `\0` → throw `Error('acp-usage: file must be an absolute path')`.
7. `apply(ctx, config)`: `const { file } = resolveConfig(config)` (a throw rejects activation), then `ctx.on('session/event', createListener({ ... }))` with `writeLine: text => process.stderr.write(text)`, `appendRecord` (only when `file` is set): `text => { fs.mkdirSync(path.dirname(file), { recursive: true }); fs.appendFileSync(file, text, { mode: 0o600 }); }` (one `appendFileSync` call per record, so the line is a single append), `warn: message => ctx.logger.warn(message)`, `now: () => new Date()`, `realpath: fs.realpathSync`. Nothing is written to stdout: it belongs to ACP.
8. `README.md` of the package, in the template's style: what it writes and when (one line and one record per finished root-Session turn), the line format and the record format with one example each, which keys are optional and why (rule 4), the config row with `file`:

   ```yaml
   - insert:
       - id: acp-usage
         name: '@kkiyama117/dsh-acp-usage'
         config:
           file: /absolute/path/to/usage.jsonl
   ```

   that subagent turns are not counted, that it reads no Session files, and how to test (`node --test tests/*.test.mjs`, synthetic events only). `locale/en.json` and `locale/ja.json` follow the template with title `ACP usage` / `ACP 使用量` and a one-sentence description.
9. Repository `README.md`: add this row to the "Plugins and presets" table right after the "Sandbox facts" row:
   `| [ACP usage](plugins/dsh-acp-usage/README.md) | Writes one token-usage line per finished ACP turn to stderr and appends the same record as JSONL to a configured file. Meant for the \`acp\` profile. |`
   `README.ja.md`: the same place after its "Sandbox facts" row:
   `| [ACP usage](plugins/dsh-acp-usage/README.md) | ACP の各ターンが終わるたびに、トークン使用量を 1 行 stderr に書き、同じ記録を設定したファイルに JSONL で追記します。\`acp\` プロファイル用です。 |`

### Tests

All in `plugins/dsh-acp-usage/tests/acp-usage.test.mjs`, `node:test` and `node:assert/strict`, synthetic objects only. Build a Session as `{ header: { id, cwd, origin? }, requestHeader: () => ({ config: { provider: 'p1', model: 'm1', reasoningEffort: 'high' } }) }` and events as `{ type, data }`. Use a listener from `createListener` with array collectors, `now: () => new Date('2026-11-22T00:00:00.000Z')` and `realpath: p => p` unless the test says otherwise. A usage chunk record is `{ type: 'chunk', time: 0, chunk: { type: 'usage', usage } }`.
