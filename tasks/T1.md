### Paths

- `ROOT` is `Path(__file__).resolve().parents[1]`: the checkout that runs the dispatcher, normally an issue worktree. `main()` uses its `root` argument everywhere in place of `ROOT`.
- The main checkout `MAIN` is the parent directory of `git rev-parse --path-format=absolute --git-common-dir` run in `root`. Compute it in a function `main_checkout(root)`.
- Card worktree: `MAIN/reports/worktrees/T<n>`, branch `card/T<n>`. Agents directory: `MAIN/reports/agents/`. `card` creates `MAIN/reports/worktrees` (`parents=True`, `exist_ok=True`) just before `git worktree add`; `_open_outputs` creates `MAIN/reports/agents` the same way just before it opens the files. Nothing else creates them, and nothing creates the card worktree directory itself (`git worktree add` does).
- `KSTACK = Path('/data/softwares/kstack')`, `WORKER = KSTACK / 'skills/kiyama-mode/scripts/run-worker.sh'`, `WORKER_ROUTE = ['dsh', 'ollama-cloud', 'deepseek-v4.1-flash', 'high']`, `REVIEW_ROUTE = ['dsh', 'openai-codex', 'gpt-6.1-sol', 'high']`, `GATE = 'python3 bin/gate.py'`.

### Cards

- A card is the file `root/tasks/T<n>.md`. `parse_card(path)` reads it. Its first line must match `^## (T[0-9]+)\. (.+)$` and the ID must equal the file name stem; otherwise raise `DispatchError(f'{path}: the first line must be "## {stem}. <title>"')`.
- The card must have a line matching `^Issue: #([0-9]+)\.?$`; otherwise raise `DispatchError(f'{path}: no "Issue: #<N>" line')`.
- `files` are the backtick-quoted strings on the line that starts with `Files:`, in order. A card without that line, or whose `Files:` line has no backticked string, raises `DispatchError(f'{path}: no "Files:" line')`; they are `fnmatch` patterns relative to the repository root. `done` is true when a line, stripped, equals `Status: done`. `text` is the whole file.
- `Card` fields: `id`, `title`, `issue` (int), `text`, `done`, `files`.
- `all_cards(root)` returns the cards of every `root/tasks/T*.md` whose stem matches `T[0-9]+`, sorted by the number as an integer (`T2` before `T10`). Every order of cards in this card is that numeric order. `tasks/README.md` is not a card. A malformed card makes `all_cards` raise, so `ambiguity` without IDs fails as a whole. `find_card(root, id)` reads only `tasks/<id>.md` and raises `DispatchError(f'no card {id} in tasks/')` when the file does not exist.

### The land branch

Cards land on `<land>`, the branch that `root` has checked out: here the issue branch, because `main` changes only through a pull request that the human merges.

- `issue_branch(root)` returns `git symbolic-ref --quiet --short HEAD` in `root`. When that fails (detached HEAD) raise `DispatchError('the checkout is not on a branch')`. When it is `main`, raise `DispatchError('the checkout is on main; run the dispatcher from the issue worktree')`. When it starts with `card/`, raise `DispatchError('the checkout is a card worktree; run the dispatcher from the issue worktree')`.
- `card` and `review` without `--main` call `issue_branch` first, then `find_card`; `land` calls `issue_branch` and never reads the card. `ambiguity` and `review --main` do not call `issue_branch`.

### Verbs

`python3 bin/dispatch.py ambiguity [ID ...]`

- With IDs, reviews those cards whatever their status, deduplicated and in numeric order (the brief and the output name `ambiguity-T2-T10` both use it, so `ambiguity T10 T2` gives that name); without IDs, every card that is not done. No card: `DispatchError('no cards to review')`.
- After `run_worker` returns (it returns `(code, answer_path)`; `main` returns `code`), read the answer and, after the `exit <n>` line, print one line per reviewed card, in card-number order: `<id>: kind1=<n> kind2=<n> kind3=<n> kind4=<n> kind5=<n> blocking=<n>`, where `blocking` is kind2 + kind4 + kind5. When the answer has no line matching `^TOTAL [0-9]+$`, print only `summary: no TOTAL line; read the answer`. Count the answer lines that split on ` | ` into at least five fields whose first field, stripped of a leading `- `, is the card ID and whose second field, stripped, is a digit 1-5. `blocking=0` is not the stop rule of card-flow section 2, which also needs every other finding answered in the card; the dispatcher cannot see answers or dismissals, so the lead judges the rule. Put the counting in `summarize_ambiguity(text, ids)`, which returns those lines (or the one `summary:` line) for `ids` sorted by card number.
- Workdir `root`, `WORKER_ROUTE`, `--read-only`. Output name `ambiguity-<ID>-<ID>...` or `ambiguity-all`.

`python3 bin/dispatch.py card ID [--no-worker]`

- Refuse, in this order, with a `DispatchError`: `issue_branch` fails; the card is done (`card {id} is done`); `git status --porcelain -- tasks/<id>.md` in `root` is not empty (`tasks/{id}.md has uncommitted changes; commit the card first`); the worktree path exists (`worktree {path} exists; land or remove it first`); branch `card/<id>` exists (`branch card/{id} already exists`).
- Before `git worktree add`, when `git status --porcelain` in `root` (untracked files count) lists anything, print `warning: the checkout has uncommitted changes; the worktree starts from <issue branch>` (for example `issue/1-x`) and go on. This check runs before `card` creates `MAIN/reports/worktrees`.
- Run `git worktree add -b card/<id> <worktree> <issue branch>` in `root` through `git(..., allow_failure=True)`. Every git command of the dispatcher passes `cwd` explicitly; these run in `root`. When it fails, remove the worktree path if it now exists (`shutil.rmtree`), run `git worktree prune`, delete `card/<id>` if it now exists (`git branch -D`), each with failures ignored, and raise `DispatchError(f'git worktree add failed: {stderr}')`.
- Print `worktree <path>`, `land <branch>`, and `gate: python3 bin/gate.py` when `bin/gate.py` exists in the new worktree, else `gate: the Done line of tasks/<id>.md`. With `--no-worker`, stop there and return 0.
- Otherwise run the worker with workdir = the card worktree, `WORKER_ROUTE`, without `--read-only`, output name `card-<id>`. Afterwards call the module function `off_list(worktree, card)`, which returns the changed paths outside `Files:` relative to the worktree root, and print `changes outside Files:` and then each path, relative to the worktree root and indented by two spaces, one per line, or `no changes outside Files`. Use the aistore `off_list` logic (`git status --porcelain -z --untracked-files=all`, non-ASCII paths unquoted) on the one worktree. Each side of a rename or copy is checked against `Files:` on its own, and each side that matches no pattern is printed.

`python3 bin/dispatch.py review ID [--main PATH ...]`

- Without `--main`: needs the card worktree (`DispatchError(f'no worktree {path}')`). The base is `git merge-base HEAD <branch>` run in the worktree, with `<branch> = issue_branch(root)`. Diff: `git diff <base>` in the worktree. Untracked files: `git ls-files --others --exclude-standard -z`, listed as absolute paths. Before the reviewer, when `bin/gate.py` exists in the worktree, run `GATE` with `shell=True` in the worktree, stdout and stderr merged; put its exit code and its last 40 lines (`(no output)` when it printed nothing) in the brief even when it fails, and print `gate exit <n>`. When `bin/gate.py` does not exist, run nothing, print `gate skipped: no bin/gate.py`, and the brief says `bin/gate.py does not exist yet; the dispatcher ran no gate.` in place of the gate lines. Workdir = the card worktree. Output name `review-<id>`.
- With `--main PATH ...`: review the lead's uncommitted change in `root`: `git diff HEAD -- <paths>` and the untracked files from `git ls-files --others --exclude-standard -z -- <paths>`, listed as absolute paths. When both are empty, `DispatchError('no changes in the given paths')`. Run or skip `GATE` in `root` the same way. Workdir = `root`. Output name `review-main-<id>`.
- Both use `REVIEW_ROUTE` with `--read-only`.

`python3 bin/dispatch.py land ID`

- Refuse, in this order, with a `DispatchError`: `issue_branch` fails; no worktree (`no worktree {path}`); the worktree is not on `card/<id>` (`the worktree is not on card/{id}`); the worktree has uncommitted or untracked changes (`the worktree has uncommitted changes`); `card/<id>` has no commits that the issue branch lacks (`card/{id} has no commits to land`); the issue branch is not an ancestor of `card/<id>` (`<branch> has moved since the dispatch. Rebase card/{id} onto <branch> in {path}, run the full gate again, then land again.`).
- Then `git merge --ff-only --no-overwrite-ignore card/<id>` in `root`. When it fails, raise `DispatchError(f'the fast-forward failed: {stderr}')` and leave the worktree and the branch in place.
- Then `git worktree remove --force <worktree>` and `git branch -d card/<id>` in `root`. If either fails, print `warning: landed, but cleanup failed: <stderr>` and still return 0. Print `landed <issue branch> <git log --oneline -1 run in root>`. Return 0.

### Outputs and the worker

- Port the aistore `run_worker` and `_open_outputs` as `run_worker(agents, name, workdir, route, brief, read_only, worker=WORKER, changed=None)` and `_open_outputs(agents, stamp, name)`, where `agents` is `main_checkout(root) / 'reports/agents'`; drop the `env` parameter. Output: `<agents dir>/<UTC %Y%m%dT%H%M%SZ>-<name>.md` holds stdout and `.log` holds stderr; a taken name gains `-2`, `-3`, ...; files are opened with mode `x`, never overwritten. The command is `[worker, '--read-only'?, workdir, *route]` with the brief on stdin. Print `answer <path>`, `log <path>`, `exit <code>`, and return `(code, answer_path)`. `main()` returns that code.
- Print `HARNESS_LINE` (keep the aistore text: this repository stops the card, as card-flow section 3 says, and does not take the External workers fallback) at most once, when either of these holds (one OR): the `.log` contains `UNKNOWN_MODEL` or `MISSING_CREDENTIAL`, whatever the exit code (card-flow section 3), or the `.log` and the `.md` are both zero bytes and `changed` is `None` or returns false (for `card`, `changed` returns whether `git status --porcelain` of the worktree is non-empty; it is called only after both files are closed). `HARNESS_LINE` is printed right after `exit <n>`, before any ambiguity summary.
- Import `from datetime import datetime, timezone` at module level, so tests can patch `dispatch.datetime` to freeze the stamp.
