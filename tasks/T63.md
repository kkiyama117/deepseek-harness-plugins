### Rules

1. `index.mjs` is plain ESM with no imports. It exports exactly: `name = 'sandbox-facts'`, `inject = ['tools']`, `factsLine(exec, result)`, `createListener(write, warn)`, and `apply(ctx)`.
2. `factsLine(exec, result)` returns a string or `undefined` and never changes its arguments. It never throws for plain data, including `undefined`, `null`, or a non-object for either argument or for `result.value`. It reads only `exec.name`, `exec.callId`, `result.isError`, `result.value` and the four `sandbox` fields. Core passes `result` as a deep-frozen JSON snapshot (`pipeline.ts`, `materializeFinalResult`) and `exec` as the frozen execution object it built itself, whose `name` and `callId` are plain data fields; throwing getters or proxies are out of scope and need no handling. `mode` may be any string; it is copied as given, not checked against a list of modes. It returns `undefined` unless all of these hold:
   - `exec` is an object, `exec.name === 'bash'`, and `typeof exec.callId === 'string'`;
   - `result` is an object, `result.isError === false`, and `result.value` is an object whose `sandbox` is a non-null object, not an array;
   - `typeof sandbox.mode === 'string'` and `typeof sandbox.denied === 'boolean'`;
   - `sandbox.enforcement` is absent (`undefined`, or the key missing), `'full'`, or `'partial'`; an explicit `null` is not absent and writes no line (Core's `SandboxEnforcement` type, `/data/softwares/deepseek-harness/packages/sandbox/sandbox/src/index.ts:67`; the bash output schema's looser `type: 'string'` does not widen it, and any other string writes no line);
   - `sandbox.runnerFailed` is absent (`undefined`, or the key missing) or a boolean; an explicit `null` writes no line.

   Otherwise it returns `JSON.stringify({ type: 'tool_facts', callId: exec.callId, tool: 'bash', sandbox: { mode, denied, enforcement, runnerFailed } }) + '\n'`, with the keys in exactly that order, where `mode` and `denied` are copied as given, `enforcement` is the value's `enforcement` or `null` when absent, and `runnerFailed` is `sandbox.runnerFailed === true`. No other field of `exec` or `result` (arguments, stdout, stderr, cwd, content) appears in the line.
3. `createListener(write, warn)` returns `(exec, result) => undefined`. The listener calls `factsLine`; when it returns a string, it calls `write(line)` exactly once with the whole line (one call per line, never split). When it returns `undefined`, it calls neither `write` nor `warn`. If `write` throws, the listener catches it, calls `warn` once with a message that starts with `sandbox-facts: write failed for ` followed by the `callId`, and returns normally. If `warn` itself throws, that is caught too. The listener never throws and never returns a promise. Only a synchronous throw from `write` is handled here; an asynchronous stdout error (such as `EPIPE` reported through an `error` event) belongs to the process's stdout, which the headless printer shares, and the plugin adds no handler for it.
4. `apply(ctx)` registers exactly one listener: `ctx.on('tools/result', createListener(chunk => process.stdout.write(chunk), message => ctx.logger.warn(message)))`. It registers nothing else and writes nothing at load time.
5. `locale/en.json`: `{"meta":{"title":"Sandbox facts","description":"Write each bash call's sandbox facts as one tool_facts line on stdout for headless --json runs."}}`. `locale/ja.json`: `{"meta":{"title":"Sandbox facts","description":"headless --json の実行で、bash の各呼び出しの sandbox の事実を tool_facts の 1 行として stdout に出力します。"}}`. Both pretty-printed with two spaces and a final newline, like `plugins/dsh-codex-transport-recovery/locale/en.json`.

### Tests

All in `tests/sandbox-facts.test.mjs`, `node:test` and `node:assert/strict`, synthetic values only, no file system, no network, no `process.stdout` writes (tests use `createListener` with a collecting `write`, or `factsLine`). Define in the test file a helper `bash(sandbox, callId = 'call-1')` that returns `[exec, result]`: `exec` is `{ name: 'bash', callId }` and `result` is `{ isError: false, value: { kind: 'foreground', cwd: '/w', exitCode: 0, signal: null, timedOut: false, aborted: false, timeoutMs: 1000, stdout: { text: 'secret-out', truncated: false }, stderr: { text: '', truncated: false }, sandbox }, content: [] }`, both frozen recursively by a `deepFreeze` helper in the test file (every nested object, including `value`, `sandbox`, `stdout` and `stderr`, is passed to `Object.freeze`). When `sandbox` is `undefined`, the helper leaves the `sandbox` key out of `value`. Other execs and results in the table are written inline.
