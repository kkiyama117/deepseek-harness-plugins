## T71. dispatch.py: start every worker through kstack's launch boundary

Issue: #99.

Tier: R1s

Needs: T70 (merged).

Spec: the Rules and Tests below are the full spec. Why: `run_worker` starts kstack's `run-worker.sh` directly, so a worker's shell can read the key files and credential-like environment that kstack's generated launch boundary hides. The boundary is applied only when a launch goes through two functions of kstack's installed policy script, `~/.config/kstack/boundary/bin/kstack-policy`; kstack's own `bin/kstack-policy-probe` loads its checkout copy of the same script as a module (and reads a `launch.json` it generated) and calls the two functions the way this card does; this card loads the installed copy and the installed `launch.json`. Their signatures, which you rely on and must not reimplement: `child_env(entry, provider, environ)` returns the environment dict for the child, and `wrap_argv(entry, argv)` returns the argv list to run (it may start with `bwrap`). `~/.config/kstack/boundary/launch.json` is a JSON object that maps entry names (here `dsh-ro` and `dsh-ws`) to entry objects. Do not open the real `launch.json`, the real policy script, or anything else under `~/.config/` in the tests or while you work; the tests use fakes. Code to change: `run_worker`, `_card` and the module docstring in `bin/dispatch.py`, `bin/test_dispatch.py`, and one sentence in `AGENTS.md`.

Files: `bin/dispatch.py`, `bin/test_dispatch.py`, `AGENTS.md`.

### Rules

1. New module names in `bin/dispatch.py`:
   - `import importlib.machinery` and `import importlib.util`.
   - `BOUNDARY = Path.home() / '.config/kstack/boundary'`, `POLICY = BOUNDARY / 'bin/kstack-policy'`, `LAUNCH = BOUNDARY / 'launch.json'`.
   - `READ_ONLY_ENTRY = 'dsh-ro'` and `WRITE_ENTRY = 'dsh-ws'`.
2. `load_boundary(entry_name)` returns `(module, entry)`:
   1. When `POLICY` or `LAUNCH` is not a regular file (decided with `os.lstat` and `stat.S_ISREG`, as kstack's own `kstack-policy verify` does, so a missing path or a symlink counts as not regular; `import stat`), raise `DispatchError(f'kstack launch boundary is not installed: {path} is missing or not a regular file; refusing to start a worker without it')`, with `path` the first of `POLICY`, `LAUNCH` (in that order) that is not a regular file.
   2. Load `POLICY` as a module the way kstack's probe does: `loader = importlib.machinery.SourceFileLoader('kstack_policy_module', str(POLICY))`, `spec = importlib.util.spec_from_loader(loader.name, loader)`, `module = importlib.util.module_from_spec(spec)`, then `loader.exec_module(module)` with `sys.dont_write_bytecode` set to `True` for the call and restored after it. When `exec_module` raises any `Exception`, or the module has no callable `child_env` or no callable `wrap_argv` (checked in that order), raise `DispatchError(f'kstack launch boundary cannot be loaded from {POLICY}: {kind}; refusing to start a worker without it')`, where `kind` is the exception's class name, or `no child_env` / `no wrap_argv`.
   3. Read `LAUNCH` as JSON (UTF-8). When reading or parsing raises `OSError`, `UnicodeDecodeError` or `ValueError`, raise `DispatchError(f'kstack launch boundary cannot be read: {LAUNCH}: {type(error).__name__}; refusing to start a worker without it')` (only the class name, never the file's content). When it is not an object, or `launch[entry_name]` is missing or not an object, raise `DispatchError(f'kstack launch boundary has no entry {entry_name} in {LAUNCH}; refusing to start a worker without it')`.
   4. Return the module and that entry object.
3. `run_worker` starts every worker through the boundary. At its very start, before `_open_outputs` (so a refusal leaves no answer or log file):
   1. `entry_name = WRITE_ENTRY if not read_only else READ_ONLY_ENTRY`; `module, entry = load_boundary(entry_name)`.
   2. `provider = route[1] if len(route) > 1 else ''` (the provider, for example `ollama-cloud`; two existing tests pass a one-element route); `environment = module.child_env(entry, provider, dict(env if env is not None else os.environ))`.
   3. `command = module.wrap_argv(entry, worker_command(worker, workdir, route, read_only))`.
   4. When `command[0] == 'bwrap'` and `shutil.which('bwrap')` is `None`, raise `DispatchError('bwrap is not installed; the kstack launch boundary needs it')`.
   Then it runs `command` with `env=environment` instead of the bare command and `env`. Everything else in `run_worker` (outputs, printed lines, return value, the harness-failure check) stays as it is. There is no fallback to a bare launch.
4. `_card`, when it will start a worker (no `--no-worker`), calls `load_boundary(WRITE_ENTRY)` and then rule 3.4's `bwrap` check on `module.wrap_argv(entry, ['true'])` right after the `Tier:`/lineage checks, before the uncommitted-changes warning, the `reports/worktrees` mkdir and `git worktree add`, so a missing boundary, entry, or `bwrap` refuses before any worktree, branch, or scope.json is made. With `--no-worker` it does not check the boundary.
5. The review record's `argv` stays `worker_command(...)` as now (the run-worker argv, which holds `--read-only`); it does not record the bwrap wrapper.
6. Module docstring: add this paragraph after the paragraph that starts `` `review` derives the run kind``:

   ```text
   Every worker starts through kstack's launch boundary: the installed
   ~/.config/kstack/boundary/bin/kstack-policy supplies child_env and
   wrap_argv for the launch.json entry dsh-ro (read-only verbs) or dsh-ws
   (card). Without the boundary or the entry the dispatcher refuses to start a
   worker; it never falls back to a bare launch.
   ```
7. `AGENTS.md`, section `Card-flow adapter`, the `Dispatcher` bullet: right after the sentence that ends `` `--kind` that differs from the derived kind needs `--reason`. ``, insert one space and the text inside the fence, which is one line, on the bullet's own line without the fence's indent. Change nothing else in `AGENTS.md`.

   ```text
   Every worker starts through kstack's launch boundary (`~/.config/kstack/boundary`, entry `dsh-ro` for read-only verbs and `dsh-ws` for `card`); when the boundary or the entry is missing, the dispatcher refuses to start the worker.
   ```

### Tests

All in `bin/test_dispatch.py`, class `DispatchTest`, synthetic data only. No test loads the real policy script, reads the real `launch.json`, or runs `bwrap`.

Helpers:
- `fake_boundary(directory, entries=('dsh-ro', 'dsh-ws'), wrap_prefix=('env', 'BOUNDARY_WRAPPED=1'), launch_text=None, without_wrap_argv=False, without_child_env=False, policy_raises=False)` writes `directory / 'boundary/bin/kstack-policy'` and `directory / 'boundary/launch.json'` and returns `(policy_path, launch_path)`. `launch.json` is `{name: {'name': name} for name in entries}`, or exactly `launch_text` when it is given. When `without_wrap_argv` is true, the policy file does not define `wrap_argv`; when `without_child_env` is true, it does not define `child_env`; when `policy_raises` is true, its first line is `raise RuntimeError('boom')`. The policy file is Python source that defines:
  - `child_env(entry, provider, environ)`: returns `{k: v for k, v in environ.items() if k != 'SECRET_TOKEN'}` plus `BOUNDARY_ENTRY` = `entry['name']` and `BOUNDARY_PROVIDER` = `provider`;
  - `wrap_argv(entry, argv)`: when `wrap_prefix[0] == 'env'`, returns `list(<wrap_prefix>) + [f"WRAP_ENTRY={entry['name']}"] + list(argv)`; otherwise `list(<wrap_prefix>) + list(argv)`.
- `setUp` creates a default fake boundary and patches `dispatch.POLICY` and `dispatch.LAUNCH` with its paths (`mock.patch.object`, stopped in cleanup), so every existing test runs through it; the default prefix `env BOUNDARY_WRAPPED=1` keeps each worker running normally.
- `fake_worker` also appends one line `entry=$BOUNDARY_ENTRY wrap=${WRAP_ENTRY-none} provider=$BOUNDARY_PROVIDER wrapped=${BOUNDARY_WRAPPED-no} secret=${SECRET_TOKEN-unset}` to `record / 'env.txt'` per run.

Every existing test keeps passing unchanged.
