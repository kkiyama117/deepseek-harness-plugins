## T21. orchestrate-agents: print the effective route recorded in one Session log

Issue: #45.

Needs: T20 (`skills/orchestrate-agents/bin/session-log-path.mjs` prints the `log` path this card reads).

Spec:
- Issue #45 (summary; the issue body is not in the worktree): to confirm which model a child Session really ran on, read its `subagent/descriptor` and `request/header` events. T20 finds the log; this card reads it and prints only the route values, never other Session content. The descriptor holds the route the parent requested for a continuable child (`agentProvider`, `agentModel`, `agentReasoningEffort`; a one-shot descriptor has none of them), and its own `provider` is the `ctx.subagents` provider name, not an LLM provider; each `request/header` records the route a request was actually prepared with. This card prints both and labels them; it does not decide which one counts. The lead updates `references/run-dsh.md` and `references/verification.md` in a separate commit; they are not part of this card.
- `skills/orchestrate-agents/references/run-dsh.md`, section "Confirm the effective model".
- Core (read only, do not write): `/data/softwares/deepseek-harness/packages/core/session/src/types.ts` (`'request/header'` event data `{ header: EpochHeader, reason }`, `EpochHeader.config`); `/data/softwares/deepseek-harness/packages/llm/llm/src/call-config.ts` (`LlmCallConfig`: `provider`, `model`, and the controls such as `reasoningEffort`); `/data/softwares/deepseek-harness/packages/core/session/src/fork.ts` (`buildForkSeed`: a forked child's log starts with the parent's events, then a `session/end-seed` event with `data.inherited: true`) and `/data/softwares/deepseek-harness/packages/subagent/subagent/src/manager.ts` (a new child appends its `subagent/descriptor` after that marker); `/data/softwares/deepseek-harness/packages/subagent/subagent/src/descriptor.ts` (`SUBAGENT_DESCRIPTOR_VERSION` 3, `SubagentDescriptorData`: `mode`, `provider`, and for continuable children `agentProvider`, `agentModel`, `agentReasoningEffort`, plus `label`, `persona`, `toolFilter`, which this card never prints); `/data/softwares/deepseek-harness/packages/session/session-persistence-jsonl/README.md`, sections "On-disk layout" and "Durability and crash semantics" (one JSON record per line; an incomplete final raw line is discarded) and "Physical encoding" (a zstd log is a concatenation of independent Zstandard frames).

### Command line

```text
node bin/session-route.mjs LOG
```

- Exactly one argument, the path of one Session log. No arguments, more than one, or an empty argument: print `Usage: ` plus the usage line above plus a newline to stderr, nothing to stdout, exit 2.
- Use Node built-ins only. Decompress with `zlib.zstdDecompressSync`; never start another program. That API exists from Node 22.15 and 23.8; when `zlib.zstdDecompressSync` is not a function and a `.jsonl.zstd` log must be read: `session-route: this Node has no zstd support (needs 22.15 or later)`, exit 1.

### Reading the log

1. Name: the basename of `LOG` must match `/^session(\.v[1-9][0-9]*)?\.jsonl(\.zstd)?$/`. Else: `session-route: not a Session log name: <basename>`, exit 1.
2. Read the file with `readFileSync`. A read error: `session-route: cannot read <LOG>: <error.code>`, exit 1.
3. A name ending in `.jsonl.zstd`: decompress the whole buffer with `zstdDecompressSync`. Unlike the backend's write path, this tool deliberately does not recover the complete frames before a torn final frame; any decompression error rejects the log. It throws: `session-route: cannot decompress <LOG>: <error.code>` (`<error.code>` is `unknown` when the error has no `code`), exit 1. The decompressed buffer, or the raw buffer for `.jsonl`, is UTF-8 text.
4. Lines: split the text on `\n`. When the text does not end with `\n`, drop its last piece (an incomplete final line). Skip empty lines.
5. Each remaining line must parse with `JSON.parse` to a plain object (not an array or `null`). Else: `session-route: <LOG>:<line number>: not a JSON event`, exit 1. Line numbers count from 1 over all pieces of the split, empty lines included.
6. Inherited prefix: find the last event whose `type` is `session/end-seed`, whose `data` is a plain object, and whose `data.inherited` is `true` (a `session/end-seed` with any other `data` is not a cut). The events before it were copied from the parent, and the marker itself was appended when the child was seeded. The count is the number of parsed events up to and including the marker (the copied events plus the marker; 0 when there is no such event). Ignore those events and ignore them below; only the events after them belong to this child.
7. Use only these events, after the inherited prefix:
   - Descriptor: the first event whose `type` is `subagent/descriptor` and whose `data` is a plain object. Its `version` is not checked.
   - Routes: every event whose `type` is `request/header` and whose `data`, `data.header` and `data.header.config` are all plain objects; any other `request/header` event is skipped. Its route is the config's `provider`, `model` and `reasoningEffort`, each kept only when present (neither `undefined` nor `null`; a missing or `null` value is absent). A config with none of the three is skipped. Two routes are the same when the three values are equal, an absent value equal only to another absent value (compare `JSON.stringify([provider, model, reasoningEffort].map(value => value ?? null))`). Keep the first event of each distinct route, in log order, with its `seq` when `seq` is a number.
   - Ignore every other event and every other field.
8. No route at all (after the inherited prefix): print nothing to stdout, print `session-route: no request/header route in <LOG>` to stderr, exit 1.

### Output

On success, stdout gets these lines, each ending with `\n`:

1. `log <LOG as given>`
2. `inherited <count>` (the count from Reading step 6)
3. `descriptor none` when there is no descriptor; else `descriptor` followed by ` <name>=<value>` for each of these keys that is present (neither `undefined` nor `null`) in the descriptor's `data`, in this order, printed under these names: `mode` as `mode`, `provider` as `subagentProvider`, `agentProvider` as `agentProvider`, `agentModel` as `agentModel`, `agentReasoningEffort` as `agentReasoningEffort`. No other descriptor key is ever printed; when none of the five is present the line is `descriptor` alone.
4. One line per distinct route, in log order: `route` followed by ` seq=<seq>` when known, then ` provider=<value>`, ` model=<value>`, ` reasoningEffort=<value>` for those present.

A `<value>` is printed as is when it is a string matching `/^[^\s=]+$/`; any other value is printed as `JSON.stringify(value)`.

- Never print any other Session content: no `label`, `persona`, `toolFilter`, message text, tool input or output, header `cwd`, or event other than the two kinds above.
- Errors go to stderr, one line each, and leave stdout empty.

### Tests

Every test writes only inside a directory from `mkdtemp(join(tmpdir(), 'session-route-'))` and removes it in `finally`. Run the script with `spawnSync(process.execPath, [script, ...args], { encoding: 'utf8' })`. All logs are synthetic; no test reads a real Session file or `~/.dsh`.

The base events, one JSON object per line, in this order:

```text
{"type":"session","version":4,"id":"child-1","createdAt":1,"cwd":"/secret/cwd","isSeeded":false,"delegationDepth":1}
{"type":"subagent/descriptor","seq":1,"data":{"version":3,"mode":"continuable","provider":"dsh","label":"SECRET-LABEL","agentProvider":"openai-codex","agentModel":"gpt-6-astra","agentReasoningEffort":"high","persona":"SECRET-PERSONA","toolFilter":{"allow":["read"]}}}
{"type":"request/header","seq":2,"data":{"reason":"initial","header":{"config":{"provider":"openai-codex","model":"gpt-6-astra","reasoningEffort":"high","maxTokens":100},"tools":[{"name":"SECRET-TOOL"}]}}}
{"type":"assistant/message","seq":3,"data":{"message":{"content":[{"type":"text","text":"SECRET-TEXT"}]}}}
{"type":"request/header","seq":4,"data":{"reason":"change","header":{"config":{"provider":"openai-codex","model":"gpt-6-astra","reasoningEffort":"high"}}}}
{"type":"request/header","seq":5,"data":{"reason":"change","header":{"config":{"provider":"ollama-cloud","model":"deepseek-v4.1-flash","reasoningEffort":"high"}}}}
```

The expected stdout for the base events, with `<LOG>` the path passed:

```text
log <LOG>
inherited 0
descriptor mode=continuable subagentProvider=dsh agentProvider=openai-codex agentModel=gpt-6-astra agentReasoningEffort=high
route seq=2 provider=openai-codex model=gpt-6-astra reasoningEffort=high
route seq=5 provider=ollama-cloud model=deepseek-v4.1-flash reasoningEffort=high
```
