### Command

`bin/live-apply.py` is a Python 3.11+ script that uses only the standard library. It starts with the same `# /// script` header as `bin/pack-local-bundle.py` (`requires-python = ">=3.11"`, `dependencies = []`). It has one subcommand now, `patch`; later cards add others, so use `argparse` subparsers.

```
python3 bin/live-apply.py patch --source SOURCE --target TARGET --record RECORD
    [--owner-approved TEXT] [--dsh-home HOME] [--run-worker PATH] [--dsh PATH]
    [--retry-delay SECONDS] [--probe-timeout SECONDS]
```

| Option | Default | Meaning |
|---|---|---|
| `--source` | required | The new patch file. Must be a regular file. |
| `--target` | required | The live patch file to replace. |
| `--record` | required | A directory for this run's record. It must not exist, or must be an empty directory. |
| `--owner-approved` | none | The owner's approval, as free text that names where it was given. Required for a production target. |
| `--dsh-home` | `$DSH_HOME` if set and not empty, else `~/.dsh` | The Harness home. Resolve it with `Path.expanduser().resolve()`. |
| `--run-worker` | `/data/softwares/kstack/skills/kiyama-mode/scripts/run-worker.sh` | The worker launcher. |
| `--dsh` | `dsh` | The DSH CLI for the config checks. |
| `--retry-delay` | `30` | Seconds to wait before the one retry of a failed model probe. Float, at least 0. |
| `--probe-timeout` | `600` | Seconds before one check is killed and counted as failed. Float, greater than 0. |

### Target routes

Let `H` be the resolved Harness home and `T = Path(--target).expanduser().absolute()` (do not resolve symlinks in `T`).

- Route `home-patch`: `T == H / 'cordis.patch.yml'`. Profile is `None`.
- Route `profile-patch`: `T == H / 'profiles' / <name> / 'cordis.patch.yml'`, where `<name>` is one path component and `H / 'profiles' / <name> / 'package.json'` is a file. Profile is `<name>`.
- Anything else is a usage error: stderr `LIVE_APPLY_USAGE: target is not a home or profile patch: <T>`, exit 2.
- If `T` exists and is a symlink, or exists and is not a regular file: stderr `LIVE_APPLY_USAGE: target is not a regular file: <T>`, exit 2.
- If `--source` is not a regular file: stderr `LIVE_APPLY_USAGE: source is not a regular file: <path>`, exit 2.
- If `--record` exists and is not an empty directory: stderr `LIVE_APPLY_USAGE: record directory is not empty: <path>`, exit 2.

`T` may be absent (a new profile patch). Its old content is then "absent".

### Production

`NON_PRODUCTION_PROFILES = frozenset({'web'})` is a module constant. A target is production when its route is `home-patch`, or when its profile is not in `NON_PRODUCTION_PROFILES`.

`SERVICE_PROFILES` is a module constant, in this order: `('headless', 'slack-intake-bridge.service')`, `('web', 'dsh-web-managed.service')`, `('ai-reference-store-daily', 'ai-reference-store-daily.service')`.

### Order of steps

1. Check the usage rules above (exit 2).
2. If `T` exists and its bytes equal the source's bytes: print the summary with status `unchanged` to stdout, exit 0. Run no check, do not create the record directory.
3. If the target is production and `--owner-approved` is missing or empty after `strip()`: stderr `LIVE_APPLY_REFUSED: <T> reaches production; pass --owner-approved with the owner's approval`, print the summary with status `refused`, exit 3. Run no check, do not create the record directory.
4. Create the record directory (`mkdir(parents=True, exist_ok=True)`). Copy the source to `RECORD/source.yml`. Copy the old target to `RECORD/backup.yml`, or, when it is absent, create the empty file `RECORD/backup-absent`.
5. Run the `before` phase. If it fails: status `pre-probe-failed`, exit 4. The target is untouched.
6. Write the source to `T` (see "Writing the target").
7. Run the `after` phase. If it passes: status `applied`; for each `(profile, service)` in `SERVICE_PROFILES` that the change reaches (all three for `home-patch`; the one whose profile equals the target's profile for `profile-patch`), print `LIVE_APPLY_RESTART_NEEDED: <service> reads this patch only at its next start` to stderr. Exit 0.
8. If the `after` phase fails: restore the old content (write `RECORD/backup.yml` back with the same writer, or unlink `T` when the old content was absent). If restoring raises `OSError`: stderr `LIVE_APPLY_ROLLBACK_FAILED: restore <T> from <RECORD>/backup.yml by hand: <error>`, status `rollback-failed`, exit 6.
9. Run the `rollback` phase. If it passes: status `rolled-back`, exit 5. If it fails: stderr `LIVE_APPLY_ROLLBACK_PROBE_FAILED: the live install still fails after the rollback`, status `rollback-failed`, exit 6.

Every exit after step 3 also writes the summary to `RECORD/summary.json`.

### Writing the target

Write to a temporary file in `T.parent` named `.<T.name>.live-apply-tmp`, flush and `os.fsync` it, set its mode to the old target's mode (`stat.S_IMODE`), or `0o600` when the old target was absent, then `os.replace` it onto `T`.

### Phases and checks

A phase runs its checks in this order and stops at the first check that fails after its retries:

1. Config checks, one per config profile. For `profile-patch`, the config profiles are `[profile]`. For `home-patch`, they are the profiles of `SERVICE_PROFILES`, in that order, keeping only those for which `H / 'profiles' / <name> / 'package.json'` is a file. A config check runs `[--dsh, '--profile', <name>, '--dump-config']`. It passes when the exit code is 0. Its name is `config-<name>`. It is never retried.
2. Model probe `worker`: route `('ollama-cloud', 'deepseek-v4.1-flash', 'high')`.
3. Model probe `review`: route `('openai-codex', 'gpt-6.1-sol', 'high')`.

A model probe creates a fresh directory with `tempfile.mkdtemp(prefix='live-apply-probe-')`, runs `[--run-worker, '--read-only', <dir>, 'dsh', <provider>, <model>, <effort>]` with that directory as `cwd` and `PROBE_TASK = 'What is 17*23? Reply with only the number.'` (UTF-8) on stdin, then removes the directory with `shutil.rmtree`. It passes when all three hold: the exit code is 0, `stdout.strip() == '391'` (`PROBE_ANSWER`), and the directory is empty when the process ends.

In the `after` and `rollback` phases, a failed model probe waits `--retry-delay` seconds and runs once more; the second result decides. In the `before` phase there is no retry.

Every child process gets the parent environment plus `DSH_HOME=<H>` and `DSH_CLI=<--dsh>`, runs with `timeout=--probe-timeout`, and has stdout and stderr captured. A timeout counts as a failed check with exit code `None`. A child that cannot start (`OSError`) counts as a failed check with exit code `None` and the error text as its stderr.

Each check attempt writes its stdout to `RECORD/<phase>-<name>-<attempt>.out` and its stderr to `RECORD/<phase>-<name>-<attempt>.err`; `<attempt>` starts at 1.

### Summary

The summary is one JSON object printed to stdout on its own line (`json.dumps(..., ensure_ascii=False)`), with these keys in this order:

| Key | Value |
|---|---|
| `status` | `unchanged`, `refused`, `pre-probe-failed`, `applied`, `rolled-back`, or `rollback-failed` |
| `route` | `home-patch` or `profile-patch` |
| `profile` | the profile name, or `null` |
| `target` | `str(T)` |
| `production` | boolean |
| `ownerApproved` | the stripped `--owner-approved` text, or `null` when missing or empty |
| `record` | the record directory as a string, or `null` when it was not created |
| `checks` | a list, in run order, of `{"phase", "name", "attempt", "ok", "exitCode", "seconds"}`; `seconds` is a float rounded to 3 places |

### Tests

`bin/test-live-apply.py` uses `unittest` and runs the script as a subprocess with `sys.executable -B`. Every test builds its own Harness home in a `tempfile.TemporaryDirectory` (profiles are directories with a `package.json` containing `{}`), passes `--dsh-home` explicitly, `--retry-delay 0`, and never runs the real `dsh` or `run-worker.sh`.

The test writes two fakes into its temporary directory as executable Python scripts (`#!` + `sys.executable`):

- Fake run-worker: reads the next line of the file named by `$FAKE_PLAN` (it keeps its position in a counter file next to the plan) and appends one JSON line `{"argv": sys.argv[1:], "target": <text of $FAKE_TARGET, or null when absent>, "dshHome": $DSH_HOME}` to `$FAKE_LOG`. Plan words: `ok` prints `391` and exits 0; `fail` prints `boom` to stderr and exits 1; `wrong` prints `392` and exits 0; `write` creates the file `stray` in its working directory, prints `391`, and exits 0; `hang` sleeps 5 seconds.
- Fake dsh: appends one JSON line `{"argv": sys.argv[1:], "dshHome": $DSH_HOME}` to `$FAKE_DSH_LOG` and exits 0, or 1 when `$FAKE_DSH_FAIL` is `1`.
