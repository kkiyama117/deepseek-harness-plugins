### Command

`bin/live-apply.py` uses only the Python 3.11+ standard library. Its first line is `#!/usr/bin/env python3`, then the same `# /// script` block as `bin/pack-local-bundle.py` (`requires-python = ">=3.11"`, `dependencies = []`), then the module docstring. It uses `argparse` subparsers with `required=True`; the only subcommand now is `patch`.

```
python3 bin/live-apply.py patch --source SOURCE --target TARGET --record RECORD
    [--owner-approved TEXT] [--dsh-home HOME] [--run-worker PATH] [--dsh PATH] [--retry-delay SECONDS]
```

| Option | Default | Meaning |
|---|---|---|
| `--source` | required | The new patch file. |
| `--target` | required | The live patch file to replace. |
| `--record` | required | A directory for this run's record. |
| `--owner-approved` | none | The owner's approval, as free text naming where it was given. The script checks only that it is not blank after `strip()`. |
| `--dsh-home` | `$DSH_HOME` if set and not blank after `strip()`, else `~/.dsh` | The Harness home. |
| `--run-worker` | `/data/softwares/kstack/skills/kiyama-mode/scripts/run-worker.sh` | The worker launcher. |
| `--dsh` | `dsh` | The DSH CLI. Config checks run it; model probes get it as `DSH_CLI`. |
| `--retry-delay` | `30` | Seconds before the one retry of a failed model probe. A float, at least 0. |

Every path option is used as `Path(value).expanduser().absolute()`, except `--dsh` when it contains no `/` (then it is a name looked up on `PATH`). `H` is the Harness home made absolute that way, and `T` is the target. In messages, `<path>` is that absolute path.

### Usage rules

Check these in order and stop at the first that fails. Each prints the message to stderr and exits 2 with nothing on stdout (`argparse` errors also exit 2, with `argparse`'s own text):

1. `--dsh-home` was given and is blank after `strip()`: `LIVE_APPLY_USAGE: --dsh-home is empty`.
2. `H` is not a directory: `LIVE_APPLY_USAGE: harness home is not a directory: <H>`.
3. `T` is neither `H / 'cordis.patch.yml'` (route `home-patch`, profile `None`) nor `H / 'profiles' / <name> / 'cordis.patch.yml'` for one path component `<name>` with `(H / 'profiles' / <name> / 'package.json').is_file()` and `<name>.lower() != 'desktop'` (route `profile-patch`, profile `<name>`): `LIVE_APPLY_USAGE: target is not a home or profile patch: <T>`. Compare the absolute paths as they are; do not resolve symlinks.
4. `(H / 'profiles' / 'headless' / 'package.json').is_file()` is false: `LIVE_APPLY_USAGE: probe profile headless does not exist in <H>`. The model probes boot `headless`, and `dsh` would create it.
5. The source is not a regular file (`Path.is_file()`): `LIVE_APPLY_USAGE: source is not a regular file: <path>`.
6. The record is `H` or inside `H` (`RECORD.is_relative_to(H)`): `LIVE_APPLY_USAGE: record directory is inside the harness home: <path>`.
7. The record exists and is not an empty directory: `LIVE_APPLY_USAGE: record directory is not empty: <path>`.

`T` may be absent on either route; its old content is then "absent".

### Production

`NON_PRODUCTION_PROFILES = frozenset({'web'})`. A target is production when its route is `home-patch`, or its profile is not in `NON_PRODUCTION_PROFILES`.

`SERVICE_PROFILES = (('headless', 'slack-intake-bridge.service'), ('web', 'dsh-web-managed.service'), ('ai-reference-store-daily', 'ai-reference-store-daily.service'))`.

### Steps

1. Check the usage rules.
2. Read the source bytes and, unless absent, the old target bytes. Each is read only here; later steps use these bytes. If `T` exists and its bytes equal the source's: status `unchanged`, exit 0. Nothing else runs and the record is not created.
3. If the target is production and `--owner-approved` is missing or blank: stderr `LIVE_APPLY_REFUSED: <T> reaches production; pass --owner-approved with the owner's approval`, status `refused`, exit 3. Nothing else runs and the record is not created.
4. Create the record directory (`mkdir(parents=True, exist_ok=True)`). Write the source bytes to `RECORD/source.yml`, and the old bytes to `RECORD/backup.yml`, or create the empty file `RECORD/backup-absent` when the old content is absent.
5. Run the `before` phase. If it fails: stderr `LIVE_APPLY_PRE_PROBE_FAILED: <check name> failed; the target was not changed`, status `pre-probe-failed`, exit 4.
6. Write the source bytes to `T`: write them to `T.parent / ('.' + T.name + '.live-apply-tmp')`, then `os.replace` that file onto `T`.
7. Run the `after` phase. If it passes: for each service of `SERVICE_PROFILES` that the change reaches (all three for `home-patch`; the one whose profile is the target's profile for `profile-patch`, or none), print `LIVE_APPLY_RESTART_NEEDED: <service> reads this patch only at its next start` to stderr. Status `applied`, exit 0.
8. If the `after` phase fails: stderr `LIVE_APPLY_AFTER_PROBE_FAILED: <check name> failed; restoring <T>`. Restore: write the old bytes to `T` the same way as step 6, or unlink `T` when the old content was absent.
9. Run the `rollback` phase. If it passes: status `rolled-back`, exit 5. If it fails: stderr `LIVE_APPLY_ROLLBACK_PROBE_FAILED: the live install still fails after the rollback`, status `rollback-failed`, exit 6.

### Phases and checks

Each of the phases `before`, `after`, and `rollback` runs these checks in order and stops at the first one that fails:

1. A config check per config profile, named `config-<name>`. The config profiles are `[profile]` for `profile-patch`, and for `home-patch` the profiles of `SERVICE_PROFILES`, in order, whose `H / 'profiles' / <name> / 'package.json'` is a file; compute this list once, in step 1. Right before each config check, check again that the profile's `package.json` is a file; if not, the check fails without starting `dsh`. A config check runs `[--dsh, '--profile', <name>, '--dump-config']` with `cwd=H` and no stdin, and passes when it exits 0. It is never retried.
2. Model probe `worker`: route `ollama-cloud deepseek-v4.1-flash high`.
3. Model probe `review`: route `openai-codex gpt-6.1-sol high`.

A model probe makes a new directory with `tempfile.mkdtemp(prefix='live-apply-probe-')`, runs `[--run-worker, '--read-only', <dir>, 'dsh', <provider>, <model>, <effort>]` with `cwd=<dir>` and `PROBE_TASK = 'What is 17*23? Reply with only the number.'` as stdin (UTF-8, no newline), and passes when the exit code is 0, `stdout.decode('utf-8', 'replace').strip() == '391'`, and `os.listdir(<dir>) == []` afterwards. Then it removes the directory with `shutil.rmtree`. Each attempt, the retry included, uses its own directory.

In the `after` and `rollback` phases, a failed model probe waits `--retry-delay` seconds and runs once more; the second attempt decides. The `before` phase never retries.

Run every child with `subprocess.run(..., capture_output=True)` and the parent environment plus `DSH_HOME=<H>` and `DSH_CLI=<--dsh>`. A child that cannot start (`OSError` from `subprocess.run`) is a failed check with exit code `None`.

Each attempt that starts a child writes its stdout bytes to `RECORD/<phase>-<name>-<attempt>.out` and its stderr bytes to `RECORD/<phase>-<name>-<attempt>.err`; `<attempt>` is 1, or 2 for a retry.

### Other errors

Any `OSError` that this card does not name above (reading the source or the target, writing the record, writing or restoring `T`, making or removing a probe directory) is handled by one rule: restore `T` as step 8 does if step 6 has started, print `live-apply: <operation>: <error>` to stderr, where `<operation>` is a short phrase such as `read source`, `write record`, `write target`, `restore target`, or `remove probe directory`, set status `error`, and exit 1. If that restore itself raises `OSError`, also print `live-apply: restore target: <error>`. Run no further phase.

### Summary

Every exit except a usage error prints one JSON object on one line to stdout (`json.dumps(summary, ensure_ascii=False)`). When the record directory exists at exit, the same object is also written to `RECORD/summary.json`. Keys, in this order:

| Key | Value |
|---|---|
| `status` | `unchanged`, `refused`, `error`, `pre-probe-failed`, `applied`, `rolled-back`, or `rollback-failed` |
| `route` | `home-patch` or `profile-patch` |
| `profile` | the profile name, or `null` |
| `target` | `str(T)` |
| `production` | boolean |
| `ownerApproved` | the stripped `--owner-approved` text, or `null` when missing or blank |
| `record` | `str(RECORD)` when the record directory exists at exit, else `null` |
| `checks` | in run order, `{"phase", "name", "attempt", "ok", "exitCode"}` for every check attempt; `[]` when none ran |
