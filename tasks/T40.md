### Command

`bin/live-apply.py` is a Python 3.11+ script that uses only the standard library. Its first line is `#!/usr/bin/env python3`, followed by the same `# /// script` block as `bin/pack-local-bundle.py` (`requires-python = ">=3.11"`, `dependencies = []`), then the module docstring. It has one subcommand now, `patch`; later cards add others, so use `argparse` subparsers with `required=True`. Running it with no subcommand is an `argparse` error (exit 2).

```
python3 bin/live-apply.py patch --source SOURCE --target TARGET --record RECORD
    [--owner-approved TEXT] [--dsh-home HOME] [--run-worker PATH] [--dsh PATH]
    [--retry-delay SECONDS] [--probe-timeout SECONDS]
```

| Option | Default | Meaning |
|---|---|---|
| `--source` | required | The new patch file. Must be a regular file. |
| `--target` | required | The live patch file to replace. |
| `--record` | required | A directory for this run's record. It must not exist, or must be an empty directory. |
| `--owner-approved` | none | The owner's approval, as free text that names where it was given. Required for a production target. The script checks only that it is not blank after `strip()`; it does not parse the text. |
| `--dsh-home` | `$DSH_HOME` if set and not blank after `strip()` (as Core's `resolveDshHome` does), else `~/.dsh`. An explicit `--dsh-home` that is blank after `strip()` is a usage error: stderr `LIVE_APPLY_USAGE: --dsh-home is empty`, exit 2. | The Harness home. Resolve it with `Path.expanduser().resolve()`; following symlinks here is deliberate and differs from Core, which resolves lexically. Children get this resolved path as `DSH_HOME`, which names the same directory. |
| `--run-worker` | `/data/softwares/kstack/skills/kiyama-mode/scripts/run-worker.sh` | The worker launcher. |
| `--dsh` | `dsh` | The DSH CLI. The config checks run it directly; the model probes get it as `DSH_CLI`, which `run-worker.sh` starts, so it applies to both. |
| `--retry-delay` | `30` | Seconds to wait before the one retry of a failed model probe. Float, at least 0. |
| `--probe-timeout` | `600` | Seconds before one check is killed and counted as failed. Float, greater than 0. |

The two numeric options use an `argparse` `type` function that raises `argparse.ArgumentTypeError` for a value that is not a float, is not finite (`math.isfinite`), or is out of range, so `argparse` prints its own error and exits 2.

### Target routes

Let `H` be the resolved Harness home and `T = Path(--target).expanduser().absolute()` (do not resolve symlinks in `T`). Route matching uses `M = T.parent.resolve() / T.name`: the parent directories are resolved, the file itself is not.

- Route `home-patch`: `M == H / 'cordis.patch.yml'`. Profile is `None`.
- Route `profile-patch`: `M == H / 'profiles' / <name> / 'cordis.patch.yml'`, where `<name>` is one path component and `(H / 'profiles' / <name> / 'package.json').is_file()` (which follows symlinks). Profile is `<name>`. A directory under `profiles/` without a `package.json` is not a DSH profile, so its patch is a usage error by design. For `profile-patch`, `<name>.lower()` must not be `desktop` (`args.ts` rejects that profile before reading any layer, so its config check could never pass), and `T.parent.name` (unresolved) must also equal `<name>` (`M.parent.name`); otherwise the target is a usage error with the route message. So a profile directory that is a symlink, to anywhere, is a usage error by design.
An `OSError` raised by any file-system call while checking these usage rules (for example `resolve`, `is_file`, `is_symlink`, `iterdir`) prints `LIVE_APPLY_ERROR: <error>` to stderr and exits 2 with nothing on stdout, like a usage error.

Check the usage rules in this order and stop at the first that fails:

- An explicit blank `--dsh-home` (see the options table).
- If `H` is not a directory: stderr `LIVE_APPLY_USAGE: harness home is not a directory: <H>`, exit 2.
- Anything that matches neither route is a usage error: stderr `LIVE_APPLY_USAGE: target is not a home or profile patch: <T>`, exit 2.
- If `T.is_symlink()` is true (also for a broken link), or `T` exists and is not a regular file: stderr `LIVE_APPLY_USAGE: target is not a regular file: <T>`, exit 2.
- If `--source` is not a regular file: stderr `LIVE_APPLY_USAGE: source is not a regular file: <path>`, exit 2.
- If `(H / 'profiles' / 'headless' / 'package.json').is_file()` is false: stderr `LIVE_APPLY_USAGE: probe profile headless does not exist in <H>`, exit 2. The model probes boot `headless` (`run-worker.sh` runs `dsh headless`), and `dsh` creates a profile that does not exist (`prepareProfile`), so the script never starts a probe without it.
- If `--record` is a symlink, or exists and is not a directory: stderr `LIVE_APPLY_USAGE: record is not a directory: <path>`, exit 2.
- If `--record` is a directory with any entry (`any(RECORD.iterdir())`; a dot-file counts): stderr `LIVE_APPLY_USAGE: record directory is not empty: <path>`, exit 2.

`--source` is checked with `Path.is_file()`, which follows symlinks, so a symlink to a regular file is accepted; the script only reads it.

`--source`, `--record`, and `--run-worker` are each used as `Path(<argument>).expanduser().absolute()` (symlinks not resolved); that value is `<path>` in these messages, `RECORD` in the rest of this card, and `record` in the summary. A usage error, including one from `argparse`, prints nothing to stdout; `-h`/`--help` keeps `argparse`'s help on stdout with exit 0 and is the one exit without a summary; `argparse` errors keep `argparse`'s own text with no `LIVE_APPLY_USAGE:` prefix. Every other exit prints the summary to stdout.

The source, the old target, and the old target's mode (`stat.S_IMODE(T.stat().st_mode)`, or `0o600` when it is absent) are each read exactly once, in step 2, the source first; every later step uses those values (step 4 copies the bytes, step 6 writes the source bytes with the old mode, step 8 restores the old bytes with the old mode) and never reads `--source` or `RECORD/backup.yml` again. Only step 8 reads `T` again, once, to compare it with the old bytes; if that comparison read raises `OSError`, step 8 treats `T` as different and restores it. If a step-2 read raises `OSError`: stderr `LIVE_APPLY_ERROR: cannot read <path>: <error>` (`<path>` is the path whose read failed first), status `error` with `oldMode` `null`, exit 2, before any check runs.

`--dsh` is used as given when it contains no `/` (a name looked up on `PATH`); otherwise it is made absolute with `Path(...).expanduser().absolute()` before any child sees it.

`T` may be absent on either route (a new patch): when `os.path.lexists(T)` is false, its old content is "absent" and step 2 does not read it. Any `OSError` while reading an existing `T` is a read error (below).

### Production

`NON_PRODUCTION_PROFILES = frozenset({'web'})` is a module constant. A target is production when its route is `home-patch`, or when its profile is not in `NON_PRODUCTION_PROFILES`. A profile that is not on that list, including one outside `SERVICE_PROFILES`, is production, as `bin/live-apply.md` says.

`SERVICE_PROFILES` is a module constant, in this order: `('headless', 'slack-intake-bridge.service')`, `('web', 'dsh-web-managed.service')`, `('ai-reference-store-daily', 'ai-reference-store-daily.service')`.

### Order of steps

1. Check the usage rules above (exit 2).
2. If `T` exists and its bytes equal the source's bytes: print the summary with status `unchanged` to stdout, exit 0. This runs before step 3 on purpose: nothing changes, so a production target needs no approval here. Run no check, and do not create or write into the record directory (an existing empty one stays empty; `record` is `null`).
3. If the target is production and `--owner-approved` is missing or empty after `strip()`: stderr `LIVE_APPLY_REFUSED: <T> reaches production; pass --owner-approved with the owner's approval`, print the summary with status `refused`, exit 3. Run no check, and do not create or write into the record directory (an existing empty one stays empty; `record` is `null`).
4. Create the record directory (`mkdir(parents=True, exist_ok=True)`) and `chmod` it to `0o700`; every file the script writes into it is `chmod`ed to `0o600`. Copy the source to `RECORD/source.yml`. Copy the old target to `RECORD/backup.yml`, or, when it is absent, create the empty file `RECORD/backup-absent`. If any of this raises `OSError`: stderr `LIVE_APPLY_ERROR: cannot write the record: <error>`, status `error`, exit 2; leave whatever was written in place (a rerun uses a new `--record`); write `summary.json` only if the directory exists, and set `record` to the path only if it exists.
5. Run the `before` phase. Its config checks rewrite `cordis.yml` as any `dsh` start does; that stays even when this phase fails, by design. If it fails: stderr `LIVE_APPLY_PRE_PROBE_FAILED: <check name> failed; the target was not changed`, status `pre-probe-failed`, exit 4. The target is untouched.
6. Write the source to `T` (see "Writing the target"). If the writer raises `OSError`: print `LIVE_APPLY_ERROR: cannot write <T>: <error>` to stderr, append `{"phase": "after", "name": "write", "attempt": 1, "ok": false, "exitCode": null, "seconds": 0.0}` to `checks` (it has no `.out` or `.err` file), skip step 7, and go to step 8 as if the `after` phase had failed. Steps 8 and 9 then decide the status and exit code (`rolled-back`/5 or `rollback-failed`/6), not `error`/2, because the target may have changed; the `LIVE_APPLY_ERROR` line is what records that the write failed.
7. Run the `after` phase. If it passes: status `applied`; for each `(profile, service)` in `SERVICE_PROFILES` that the change reaches (all three for `home-patch`; the one whose profile equals the target's profile for `profile-patch`), print `LIVE_APPLY_RESTART_NEEDED: <service> reads this patch only at its next start` to stderr. For `home-patch` these are always all three lines, whether or not the profile directories exist. A `profile-patch` whose profile is not in `SERVICE_PROFILES` prints no such line. Exit 0.
8. If the `after` phase fails: print `LIVE_APPLY_AFTER_PROBE_FAILED: <check name> failed; restoring <T>` to stderr (`<check name>` is `write` when step 6 failed), then restore the old content. When the old content was absent: if `os.path.lexists(T)` is false, restoring does nothing and succeeds; otherwise unlink `T` with `T.unlink(missing_ok=True)`. When the old content existed: if `T` holds exactly the old bytes, restoring writes nothing and succeeds; otherwise write the old bytes back with the same writer. If restoring raises `OSError`: stderr `LIVE_APPLY_ROLLBACK_FAILED: restore <T> from <RECORD>/backup.yml with mode <oldMode> by hand: <error>` (`<oldMode>` is the same text as the summary's `oldMode`, such as `0o640`) (when the old content was absent: `LIVE_APPLY_ROLLBACK_FAILED: remove <T> by hand: <error>`), status `rollback-failed`, exit 6. Run no `rollback` phase.
9. Run the `rollback` phase. If it passes: status `rolled-back`, exit 5. If it fails: stderr `LIVE_APPLY_ROLLBACK_PROBE_FAILED: the live install still fails after the rollback`, status `rollback-failed`, exit 6.

Every exit after step 4 has created the record directory also writes the summary to `RECORD/summary.json`: the same object as stdout, as `json.dumps(summary, ensure_ascii=False, indent=2)` plus a final newline. An `OSError` while writing `summary.json` prints `LIVE_APPLY_ERROR: cannot write the record: <error>` to stderr and changes neither the status nor the exit code.

### Writing the target

Write to a temporary file in `T.parent` named `.<T.name>.live-apply-tmp`, opened with mode `'wb'` so that a stale file of that name left by an earlier crash is truncated and reused, flush and `os.fsync` it, set its mode with `os.chmod` to the old mode read in step 2 (`0o600` for a new target, whatever the umask), then `os.replace` it onto `T`. Steps 6 and 8 use this one writer; whenever it raises `OSError`, it first removes the temporary file if it exists, ignoring an `OSError` from that removal, so no temporary file is left in the live directory.

### Phases and checks

Every phase (`before`, `after`, `rollback`) runs the same checks, in this order, and stops at the first check that fails after its retries:

The script never writes `profiles/<name>/cordis.yml`. The `--dump-config` child rewrites it, as every `dsh` start does (`bin/live-apply.md`, "liveを読むもの"); that file is outside the backup on purpose.

1. Config checks, one per config profile. For `profile-patch`, the config profiles are `[profile]`. For `home-patch`, they are the profiles of `SERVICE_PROFILES`, in that order, keeping only those for which `H / 'profiles' / <name> / 'package.json'` is a file. Other profiles are not checked, even though a home patch reaches them; that is deliberate. Immediately before each config check, the script checks again that `(H / 'profiles' / <name> / 'package.json').is_file()`; if it is false, that check fails with exit code `None` and `dsh` is not started, because `dsh` would create the missing profile. A config check runs `[--dsh, '--profile', <name>, '--dump-config']` with `cwd=H` and stdin `subprocess.DEVNULL`. It passes when the exit code is 0. `runDumpConfig` reads the profile's bundle layers, its profile patch, and the home patch (`collectConfigDumpLayers`) without composing or booting the tree, so a broken home patch fails the config check of every profile, as intended; so a nonzero exit means a layer could not be found or parsed, and exit 0 does not prove that the tree boots. The model probes boot only the `headless` profile (`run-worker.sh` always runs `dsh headless`); booting any other profile is out of scope for this card on purpose, because booting `web` starts a server. Its name is `config-<name>` and its `attempt` is always `1`. It is never retried.
2. Model probe `worker`: route `('ollama-cloud', 'deepseek-v4.1-flash', 'high')`.
3. Model probe `review`: route `('openai-codex', 'gpt-6.1-sol', 'high')`.

Each attempt of a model probe, including the retry, creates its own fresh directory with `tempfile.mkdtemp(prefix='live-apply-probe-')` in the system temporary directory, runs `[--run-worker, '--read-only', <dir>, 'dsh', <provider>, <model>, <effort>]` with that directory as `cwd` and `PROBE_TASK = 'What is 17*23? Reply with only the number.'` (UTF-8, no trailing newline) sent with `communicate(input=...)`, which closes stdin, then removes the directory with `shutil.rmtree`. It passes when all three hold: the exit code is 0, `stdout.strip() == '391'` (`PROBE_ANSWER`), and `os.listdir(<dir>) == []` when the process ends (a dot-file or a subdirectory counts as an entry). A patch that makes DSH write into the working directory, for example by moving the session root there, breaks every worker run, so a non-empty directory is a failure of the patch and triggers the rollback like any other failed probe. Check the directory before removing it; an `OSError` from `os.listdir` fails the attempt like the `mkdtemp`/`rmtree` errors below.

In the `after` and `rollback` phases, a failed attempt of a model probe, whatever made it fail (including the `OSError` cases below, except a failed write of its `.out`/`.err` file), waits `--retry-delay` seconds and runs once more; the second result decides. In the `before` phase there is no retry. Config checks are never retried.

Every child process gets the parent environment plus `DSH_HOME=<H>` and `DSH_CLI=<--dsh>` (`dsh` reads its home from `DSH_HOME`, Core `packages/util/home-paths`; `run-worker.sh` passes its environment through unchanged), is started with `subprocess.Popen(..., start_new_session=True)`, and has stdout and stderr captured as bytes; wait with `communicate(timeout=--probe-timeout)`. On timeout, kill the whole process group with `os.killpg(proc.pid, signal.SIGKILL)`, ignoring `ProcessLookupError`, collect the output with `communicate()`, and count the check as failed with exit code `None`; the empty-directory condition is not evaluated. A child that cannot start (`OSError` from `Popen`) counts as a failed check with exit code `None` and the error text as its stderr. For the answer, decode stdout as UTF-8 with `errors='replace'`. An `OSError` from `mkdtemp` or `rmtree` fails that attempt, even when the three conditions above held, because the probe left state behind; its exit code is the child's, or `None` when no child ran. Its error text is written to the attempt's `.err` file, after the child's stderr when a child ran; no `LIVE_APPLY_ERROR` line is printed for it.

`seconds` measures only the child, with `time.monotonic()` from just before `Popen` to just after the process has ended; it excludes the retry wait and the directory check, and is `0.0` when the child could not start.

Each check attempt writes its raw stdout bytes to `RECORD/<phase>-<name>-<attempt>.out` and its raw stderr bytes to `RECORD/<phase>-<name>-<attempt>.err`; `<attempt>` starts at 1. Both files are attempted even when the first write fails. An `OSError` while writing either file fails that attempt (no retry) and prints `LIVE_APPLY_ERROR: cannot write the record: <error>` to stderr, once per failed file; the attempt still appears in `checks` with `ok` false, the child's exit code, and the measured `seconds`.

### Summary

The summary is one JSON object printed to stdout on its own line (`json.dumps(..., ensure_ascii=False)`), with these keys in this order:

| Key | Value |
|---|---|
| `status` | `unchanged`, `refused`, `error`, `pre-probe-failed`, `applied`, `rolled-back`, or `rollback-failed` |
| `route` | `home-patch` or `profile-patch` |
| `profile` | the profile name, or `null` |
| `target` | `str(T)` |
| `production` | boolean |
| `ownerApproved` | the stripped `--owner-approved` text, or `null` when missing or empty |
| `record` | `str(RECORD)` when step 4 has started and the directory exists at exit, whether the script created it or found it empty; else `null` |
| `oldMode` | the old mode from step 2 as `oct(mode)` (for example `0o640`), or `null` when the old content was absent |
| `checks` | a list, in run order, of `{"phase", "name", "attempt", "ok", "exitCode", "seconds"}`; `seconds` is a float rounded to 3 places; `[]` when no check ran |

### Tests

`bin/test-live-apply.py` uses `unittest`, ends with `if __name__ == '__main__': unittest.main()`, and runs the script as a subprocess with `sys.executable -B`. Every test builds its own Harness home in a `tempfile.TemporaryDirectory` (profiles are directories with a `package.json` containing `{}`; every home has `profiles/headless` unless the test row says otherwise), passes `--dsh-home`, `--retry-delay 0`, `--run-worker <absolute path of the fake run-worker>`, and `--dsh <absolute path of the fake dsh>` explicitly, and never runs the real `dsh` or `run-worker.sh`. Temporary directories are made with `tempfile.TemporaryDirectory()` in the system temporary directory. Each test also runs the script with `TMPDIR=<test temp>/tmp` (an empty directory the test creates), so the script's probe directories land there, and asserts that this directory is empty when the script exits.

The test writes two fakes into its temporary directory as executable Python scripts (`#!` + `sys.executable`):

- Fake run-worker: reads the next line of the file named by `$FAKE_PLAN` (it keeps its position in a counter file next to the plan) and appends one JSON line `{"argv": sys.argv[1:], "stdin": <all of stdin as text>, "cwd": os.getcwd(), "dshCli": $DSH_CLI, "target": <the text of the file whose path is $FAKE_TARGET, read at call time, or null when that file does not exist>, "dshHome": $DSH_HOME}` to `$FAKE_LOG`. When the plan is used up, it prints `plan exhausted` to stderr and exits 99. Plan words: `ok` prints `391` and exits 0; `fail` prints `boom` to stderr and exits 1; `wrong` prints `392` and exits 0; `write` creates the file `stray` in its working directory, prints `391`, and exits 0; `hang` sleeps 5 seconds, then prints `391` and exits 0.
