### Rules

1. Shared helpers in `bin/dispatch.py`:
   - `refresh_base(main, card_id, branch, scope)`: the base refresh that is now step 2 of `gate_step`, moved here unchanged: for each entry it prints `base {name} {old} -> {new}` when the base moves, and an `OSError` from `write_scope` raises `DispatchError(f'cannot write scope.json: {error}')`. `gate_step` calls it instead of its own loop.
   - `current_states(scope)`: `{entry['name']: work_state(entry['path'])}` for every entry of `scope['repos']`, then of `scope.get('gate_repos') or []`. `gate_step` and `_review`'s gate reuse check both call it.
   - `repo_states(scope)`: the same for `scope['repos']` only. `_review` uses it for `state` and `state_after`.
   - `parse_answer(path)` reads the file (UTF-8, `errors='replace'`) and returns `(findings, complete)`. Lines inside fences are skipped: a line matching `FENCE` toggles the fence and is skipped itself. `findings` is the list of the other lines that match `FINDING`, in order. `complete` is true when some other line matches `^TOTAL\s+\d+\s*$` and no other line matches `^STOPPED\b`. `_review` prints `finding <seq>.<k> <line>` from this list, as now.
   - `read_findings(directory)` reads `directory / 'findings.tsv'`. It returns `None` when the file does not exist. Otherwise it skips the first line (the header) and every empty line, splits each other line on `'\t'`, and returns `{id: (disposition, detail)}` with all three fields stripped. A line that does not have exactly 3 fields maps its stripped first field to `('', '')`, so the dispose check refuses it, as kstack-accept's `load_findings` rejects it.
2. Review order in worktree mode. `_review` keeps every existing step and its order, with these changes:
   1. After `read_scope`: `refresh_base(main, card.id, branch, scope)`, so the base is refreshed also when gate.json is reused.
   2. The gate reuse check compares gate.json's `states` with `current_states(scope)`.
   3. Right after `state = repo_states(scope)`: for each entry of `scope['repos']`, when `state[name]` differs from the stripped stdout of `git rev-parse HEAD^{tree}` in `entry['path']`, raise `DispatchError(f'commit the worktree first: {name} has changes that HEAD does not hold')`. No worker runs.
   4. `heads = {name: git rev-parse HEAD in entry['path']}` and `bases = {name: entry['base']}` (after the refresh) for every entry of `scope['repos']`.
   5. The brief is built after steps 3 and 4 and after the kind is chosen (rules 4 and 5), so that the fix-check block (rule 6) can use them; the diff and untracked list are computed as now. This is the only step that moves.
3. Dispose check. It runs right after `seq` is computed and the `needs an earlier round or fixcheck` refusal, before the gate step, so it wins over a failing gate or a dirty worktree. `rows = read_findings(directory)`. For each review record that is not `optional` (that is, `round`, `fixcheck` and `supplement` records), in order of `seq`: `findings, _ = parse_answer(record['answer'])`; for `k` from 1 to `len(findings)`: when `rows` is `None` or has no key `f'{seq}.{k}'`, raise `DispatchError(f'dispose the findings of run {seq} first: findings.tsv has no row {seq}.{k}')`; when that row's disposition is not `fixed`, `wrong` or `open`, or its detail is empty, raise `DispatchError(f'dispose the findings of run {seq} first: row {seq}.{k} needs fixed, wrong or open and a detail')`. An answer file that cannot be read raises `DispatchError(f'bad review record {record path}: cannot read {answer path}')`. `read_findings` itself stays lenient; this check is the strict one.
4. Derived kind. `lineage = implementer_lineage(REVIEW_ROUTE)`; `rounds` = the history's `round` records; `latest_round` = the last of them or `None`. A fixed high is a finding whose `FINDING` match has severity `high` (any case) and whose row's disposition is `fixed`. (An `open` high is real but cannot lead to round 2: kstack's `REVIEW_ROUND_CAP` accepts round 2 only after a high disposed `fixed` after a state change.) `derived` is, checking in this order:
   1. `'round'` when `rounds` is empty;
   2. `'round'` when `latest_round['state'] == state` and no record in `rounds` has `lineage == lineage` and `round == latest_round['round']`;
   3. `'round'` when `rounds` has a `round` 1 record, no record in `rounds` has `round` 2, and some history record that is either a `round` record with `round` 1 or a `fixcheck` record whose `seq` is greater than the `seq` of the first `round` 1 record has a fixed high and a `state` different from `state` (the same sources kstack-accept's `REVIEW_ROUND_CAP` accepts). Without a `round` 1 record, case 3 is false;
   4. `'fixcheck'` otherwise.
5. Kind flags. `--kind` now defaults to `None`, and `review` gains `--reason` (a string, default `None`).
   1. The existing refusal `review --kind {kind} needs an earlier round or fixcheck` stays, for `--kind fixcheck` and `--kind supplement`, and runs first.
   2. With no `--kind`, the kind is `derived`; print `kind {derived} (derived)`.
   3. `--kind supplement` and `--kind optional` are used as given and never compared.
   4. `--kind round` or `--kind fixcheck` equal to `derived` is used; print `kind {derived} (derived)` and ignore `--reason`. When it differs and `--reason` is not given or is empty, raise `DispatchError(f'--kind {kind} differs from the derived kind {derived}; pass --reason to override')`. When it differs and `--reason` is given, print `kind {kind} instead of derived {derived}: {reason}` and use it.
   The `round`, `covers` and `covers_from` values are then computed from the chosen kind exactly as now.
6. Fixcheck brief. When the chosen kind is `fixcheck`, `covered` is the last history record (the run `covers_from` points at). `review_brief` gains a keyword `fixcheck_block=''` (so its existing eight-argument calls keep working), and `REVIEW_BRIEF` gains a `{fixcheck_block}` placeholder on its own paragraph, right after the untracked-files list; for every other kind it is `''`, and the paragraph is left out (no extra blank lines). When `covered` has no `heads` object, or its `heads` has no `LAND_REPO` key (a record written before this card), print `warning: run {seq} has no heads; the fix check shows the full diff` and use `''` for the whole block (no delta, no range-diff, no findings list). Otherwise the block is, with each `<...>` filled in. When `bases[LAND_REPO]` equals `covered['bases'][LAND_REPO]` (a missing `bases` object, or one without the `LAND_REPO` key, counts as equal), it starts with:

   ````text
   This run is a fix check of run <covered seq>. Change since that run (`git diff <covered head> HEAD`):

   ```diff
   <git diff <covered head> HEAD in the worktree>
   ```
   ````

   When the base moved, that diff would also hold the land branch's moves, which their own cards reviewed (acceptance section 5), so the block starts instead with:

   ````text
   This run is a fix check of run <covered seq>. The base moved since that run, so here is how the card's own diff changed (`git range-diff <old base>..<covered head> <base>..HEAD`):

   ```text
   <that range-diff in the worktree>
   ```
   ````

   and then by:

   ```text

   Findings of the covered run, as the lead disposed them (id | disposition | detail | finding):
   <one line per finding: "- <id> | <disposition> | <detail> | <finding line>", or "- none">

   Check that each finding disposed `fixed` is fixed by the change, and report any defect the change adds.
   ```

   The covered findings are those of `covered` and, when `covered` is a `round` record, of the `round` records that come right before it in the history (the `round` and `fixcheck` records only; `optional` and `supplement` records are skipped), walking back while each has the same `round` and `state` and stopping at the first `fixcheck` record or any record that differs, listed in `seq` order and then `k` order. `<covered head>` and `<old base>` are `covered['heads'][LAND_REPO]` and `covered['bases'][LAND_REPO]`.
7. Incomplete answers (kstack issue #126). After the existing nonzero-exit rule: when the worker's exit is 0, the chosen kind is `round` or `fixcheck` (a `supplement` is the lead's choice and keeps its kind), and `parse_answer(answer)` gives `complete` false: with no finding line, print `review-{seq}.json written as optional: the answer is incomplete and has no finding`, set `kind = 'optional'` and `round`, `covers`, `covers_from` to `None`; with at least one finding line, print `review-{seq}.json keeps kind {kind}: the answer is incomplete but has {n} finding lines` and keep the kind.
8. The review record gains two keys after `covers_from`, in this order: `'heads': heads`, `'bases': bases`.
9. Module docstring: change the usage line to `    python3 bin/dispatch.py review ID [--kind KIND [--reason TEXT]] [--main PATH ...]`, and add this paragraph after the paragraph that starts `` `land` reads KSTACK_ACCEPT``:

   ```text
   `review` derives the run kind from the earlier review records and
   findings.tsv (kstack acceptance section 5), refuses until every finding of
   an earlier run that is not optional has a findings.tsv row, and refuses a worktree whose state is
   not committed. A fix check's brief adds the change since the covered run, a
   range-diff when the base moved, and the covered findings.
   ```
10. `AGENTS.md`, section `Card-flow adapter`, the `Dispatcher` bullet: replace `review ID [--kind KIND] [--main PATH ...]` with `review ID [--kind KIND [--reason TEXT]] [--main PATH ...]`, and right after the sentence that ends `` lines that `review` prints. `` insert one space and the text inside the fence, which is one line, on the bullet's own line without the fence's indent. Change nothing else in `AGENTS.md`.

    ```text

    ```
