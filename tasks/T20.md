### Command line

```text
node bin/session-log-path.mjs (--profile NAME [--patch PATH]... | --dump-file PATH) [--session-id ID]
```

- Exactly one of `--profile` and `--dump-file`. `--patch` is repeatable, keeps its order, and is allowed only with `--profile`. `--session-id` is optional. Options may come in any order. Each option takes the next argument as its value, even when that argument starts with `--`; a value is missing only when there is no next argument.
- Usage errors: any other argument; a missing value; an empty value (`''`) for any option; `--profile`, `--dump-file` or `--session-id` given more than once; both or neither of `--profile` and `--dump-file`; `--patch` with `--dump-file`. For each, print exactly the usage line above, prefixed with `Usage: `, plus a newline, to stderr and exit 2. Check usage before doing anything else.
- Use Node built-ins only. No YAML library.

### Getting the dump

- `--dump-file PATH`: read that file as UTF-8. A read error: `session-log-path: cannot read the dump file: <error.code>`, exit 1.
- `--profile NAME`: `NAME` must match `/^[A-Za-z0-9][A-Za-z0-9._-]*$/`, else it is a usage error (the same usage line on stderr, exit 2, checked with the other usage errors). Before starting dsh, check that `<home>/profiles/<NAME>/package.json` exists, with `<home>` resolved as in Parsing rule 7 (`DSH_HOME`, else `~/.dsh`); if it does not: `session-log-path: profile <NAME> does not exist under <home>/profiles; refusing to let dsh create it`, exit 1. Like every dsh start, `--dump-config` rewrites the profile's fixed `cordis.yml` and may normalize its `package.json` (Core `apps/cli/src/profile-boot.ts`, `prepareProfile`); the lookup accepts these writes because every worker start makes them too, and `loadProfile` (Core `packages/boot/app-boot/src/index.ts`) initializes a missing profile when its name is a shipped template such as `web`. The check refuses that initialization on purpose: a lookup must not create a profile. For other names it only replaces dsh's own error with this one. Then run the executable named by the environment variable `DSH_CLI`, or `dsh` when `DSH_CLI` is unset or blank after trimming (a non-blank `DSH_CLI` is used exactly as set, untrimmed), with `spawnSync` (no shell) and exactly these arguments: `--profile NAME`, then `--patch PATH` for each patch in order, then `--dump-config`. Use `encoding: 'utf8'` and `maxBuffer: 64 * 1024 * 1024`; pass no `cwd` or `env`, so the child inherits the caller's working directory and environment (including `DSH_HOME` and `HOME`).
  - Check in this order. `result.error` is set: `session-log-path: dsh --dump-config failed to start: <result.error.code>`, exit 1. `result.status` is `null`: `session-log-path: dsh --dump-config was killed by <result.signal>`, exit 1. `result.status` is not 0: `session-log-path: dsh --dump-config exited <result.status>`, exit 1.
  - Never print the child's stdout or stderr.

### Dump format

The dump is YAML. A comment line `# == <layer>` names the layer of the rows that follow it, up to the next such comment. A top-level row starts at a line that begins with `- ` in column 0. Rows usually start with `- id: <id>`, but key order is not guaranteed, so the id may instead be a later line `  id: <id>` of the row. Example (synthetic):

```yaml
# == @deepseek-ai/dsh-base, patched by /home/u/.dsh/cordis.patch.yml
- id: session-persistence-jsonl
  name: '@deepseek-ai/dsh-session-persistence-jsonl'
  config:
    root: /srv/dsh/sessions
- id: attachment-local
  name: '@deepseek-ai/dsh-attachment-local'
  config:
    dshHome: /srv/dsh
# == @deepseek-ai/dsh-base
- id: storage-json
  config:
    root: !!js dshHomePath('storages')
```

### Parsing

Split the dump on `\n` (drop a trailing `\r` from each line). Check the rules in this order; the first one that fails decides the error.

1. Rows: a top-level row is the lines from a line that starts with `- ` in column 0 up to, not including, the next non-empty line that does not start with a space (or the end); empty lines inside belong to the row, but empty lines at the row's end (before the next row, a comment, or the end of the dump) do not. Its id is the value of its first line when that line matches `/^- id: (.+)$/`, else of its first line that matches `/^  id: (.+)$/`; a row without either has no id. Its name is found the same way with `name` instead of `id`. For both, remove one pair of matching surrounding `'` or `"` from the trimmed value before comparing. Only top-level rows are read; rows nested inside another row (for example under `group: true`, or patch entries inside an include row's config) are ignored.
2. Row: the top-level rows whose id is `session-persistence-jsonl`, plus the rows without an id whose name is `@deepseek-ai/dsh-session-persistence-jsonl`. None: `session-log-path: no top-level session-persistence-jsonl row in the composed config`, exit 1. More than one (the dump is composed, so this means a malformed dump): `session-log-path: more than one session-persistence-jsonl row in the composed config`, exit 1.
3. Layer: the text after `# == ` on the nearest line above the row start that starts with `# == `; `unknown` when there is none.
4. Disabled: a row line matching `/^  disabled: (.*)$/`. Trim the value. Value `false`, `null`, `~` or empty: carry on (the Loader treats them as enabled). Value `true`: `session-log-path: session-persistence-jsonl is disabled in the composed config`, exit 1. Any other value, including a `!!js` expression the tool cannot evaluate: `session-log-path: cannot read the disabled value: <value>`, exit 1.
5. Root: the row's line equal to `  config:`, then, among the row's own lines after it (never lines of a later row) that start with four spaces, the first that matches `/^    root: (.+)$/`. No `  config:` line, or no root line: `session-log-path: the session-persistence-jsonl row has no config.root`, exit 1.
6. Compression: among the row's own lines after `  config:` that start with four spaces (the lines rule 5 searches), a line matching `/^    compression: (.+)$/`. Its trimmed value with one pair of matching surrounding `'` or `"` removed must be `none` or `zstd`: `none` selects the suffix `.jsonl` and makes `.jsonl.zstd` the other suffix; `zstd`, or no line, selects `.jsonl.zstd` and makes `.jsonl` the other suffix. Any other value: `session-log-path: cannot read the compression value: <trimmed value>`, exit 1. Rule 7 applies to the root only.
7. Scalar values, after trimming. Let `v` be the value, and `w` be `v` without a leading `!!js ` when `v` starts with it, else `v`:
   - `w` is exactly `>-`: the continuation lines are the row lines after the root line up to, not including, the next non-empty line with four or fewer leading spaces (or the row's end). If there is at least one, none is empty, and all have the same leading spaces (more than four), js-yaml folded a long value: replace `v` with those lines, trimmed and joined with single spaces, prefixed with `!!js ` when `v` started with `!!js `, recompute `w`, and apply these cases again from the top. A value is folded at most once: when `w` is still `>-` after a fold, it is the block scalar case below. Otherwise it is the block scalar case below;
   - `w` starts with `>` or `|` (any other YAML block scalar): `session-log-path: the root is a YAML block scalar, which this tool does not read`, exit 1;
   - `v` starts with `'` and ends with `'`: the text between them, with each `''` replaced by `'`;
   - `v` starts with `"` and ends with `"`: `JSON.parse(v)`; if it throws: `session-log-path: cannot read the quoted root: <v>`, exit 1;
   - `v` matches `/^!!js dshHomePath\((.*)\)$/` and the inner text matches, as a whole, `/^\s*(?:(?:'[^']*'|"[^"]*")(?:\s*,\s*(?:'[^']*'|"[^"]*"))*)?\s*$/` (empty, or string literals separated by commas; a comma inside quotes belongs to its literal, so `'a,b'` is one literal `a,b`). Each literal is the raw text between its quotes, with no escape processing: the value is `path.join(home, ...literals)`, where `home` is `path.resolve(expandHome(DSH_HOME))` when the environment variable `DSH_HOME` is set and not blank after trimming, else `path.join(os.homedir(), '.dsh')`. `expandHome` is `expandHomePath`: it maps `~` to `os.homedir()` and a leading `~/` or `~\` to `path.join(os.homedir(), rest)`, and leaves other values unchanged;
   - any other `v` starting with `!!js`: `session-log-path: cannot evaluate the JavaScript root: <w>`, exit 1. Never evaluate it;
   - anything else: `v` as written.
8. The root must be absolute (`path.isAbsolute`): else `session-log-path: root is not an absolute path: <root>`, exit 1. This deliberately fails closed on `~` and relative paths: do not expand them. An absolute root is then normalized with `path.resolve`, and the normalized root is the `<root>` in every output line and message.

### Output

- On success, stdout gets `root <root>` then `layer <layer>`, one per line.
- With `--session-id ID`, find the log with the layout and selection rules of the backend's `findLog` and `resolveGenerationInDirectory` (`/data/softwares/deepseek-harness/packages/session/session-persistence-jsonl/src/index.ts`), with three deliberate differences: entries are visited in sorted order, legacy flat files are ignored, and the root-wide other-suffix check that the backend runs first (`ensureRootEncoding`) is not done; only the matched session directories are checked for the other suffix. Errors are reported in the order the steps below meet them: the root listing, then each project directory in order (its listing, then its other-suffix check), then the duplicate check after all project directories, then no match.
  - Encode `ID` exactly like `encodeSegment` in `format.ts`: when the whole id is `.` it becomes `~002E`, and when the whole id is `..` it becomes `~002E~002E`; otherwise each UTF-16 code unit that is `~` or not in `[A-Za-z0-9._-]` becomes `~` plus its four-digit uppercase hex code, and every other unit (including `.` inside a longer id) stays as it is.
  - Project directories: `readdir(root, { withFileTypes: true })`, keeping the entries whose `isDirectory()` is true, sorted by name (default JavaScript string order). `ENOENT` on the root means no project directories. Legacy flat files directly in a project directory (`<encoded>.jsonl[.zstd]`) are out of scope and ignored.
  - Session directory: for each project directory `P` in that order, `readdir(join(P, encoded), { withFileTypes: true })`, with the entries sorted by name. `ENOENT` means no match in `P`.
  - Generations: entries named `session<suffix>` (version 0) or `session.v<N><suffix>` where `N` matches `/^[1-9][0-9]*$/` and `Number.isSafeInteger(Number(N))` (as `parseSessionFormatLogFilename` in `/data/softwares/deepseek-harness/packages/session/session-format/src/filename.ts`), with the selected suffix, whatever their entry type. If any entry has such a name with the other suffix: `session-log-path: <path of the first such entry in sorted order, in the first project directory that has one> uses <other suffix>, but the config selects <suffix>`, exit 1. Ignore every other entry. A directory with no generation is no match. Otherwise pick the highest version, compared as integers.
  - More than one project directory has a match: `session-log-path: session id <ID> appears in more than one project directory: <the matching session directories, sorted, joined by ", ">`, exit 1.
  - Any other filesystem error: `session-log-path: cannot read <path>: <error.code>`, exit 1, where `<path>` is the directory whose `readdir` failed.
  - Exactly one match: print `log <absolute path of the picked file>` after the `layer` line.
  - Use only directory listings. Never open or read a Session file.
  - No match: print nothing to stdout, print these three lines to stderr, and exit 1:

    ```text
    session-log-path: no session log for <ID>
    searched: <root>/*/<encoded>/
    effective root: <root> (<layer>)
    ```

- On every error, stdout is empty.
- Never print any other part of the dump, on success or failure. The only dump text an output line or error may print is `<layer>` and the one scalar its message names (`<value>`, `<w>`, `<v>`, `<root>`).
- Never fall back to `~/.dsh/sessions` or any other root than the one the dump gives.
- Exit 0 on success.

Unless a row says otherwise, a test's dump is the "Dump format" example, every row of it including `attachment-local`, with only the named line changed or added, `<layer>` is `@deepseek-ai/dsh-base, patched by /home/u/.dsh/cordis.patch.yml`, and the `root:` line of the `session-persistence-jsonl` row holds `<root>`, a directory the test creates under its temp dir. The `storage-json` row stays as in the example. "The root line" always means the `session-persistence-jsonl` row's root line.
