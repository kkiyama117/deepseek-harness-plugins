## T23. orchestrate-agents: stop at the config block, and refuse a seeded log without its marker

Issue: #45.

Needs: T20, T21 (both committed: `skills/orchestrate-agents/bin/session-log-path.mjs`, `skills/orchestrate-agents/bin/session-route.mjs` and their tests).

Spec:
- Second review of PR #55 (gpt-6-astra, privacy): two real findings this card fixes.
  1. `session-log-path.mjs` searches for `root` and `compression` in every four-space line after `  config:` until the row ends, so it also reads lines under a later key of the same row. Reproduced: a row with `  config:`, `    root: /srv/x`, `  meta:`, `    compression: SECRET-VALUE-123` exits 1 and prints `SECRET-VALUE-123` in the error; a row with `  config:`, `    compression: none`, `  meta:`, `    root: /srv/other` prints `root /srv/other`.
  2. `session-route.mjs` trusts the inherited marker to find a forked child's own events. When the log's `session` header says `isSeeded: true` but no tagged marker was read (for example, the log ends inside the marker line), every event counts as the child's, so a parent's route is printed as the child's.
- `tasks/T20.md` (Parsing rules 5 and 6; rule 7's fold continuation already stops at a line with four or fewer leading spaces, so it stays inside the config block and is unchanged) and `tasks/T21.md` (a new check between Reading steps 6 and 7): the rules this card changes; every other rule stays. The lead updates `references/run-dsh.md` in a separate commit; it is not part of this card.
- Core (read only): `/data/softwares/deepseek-harness/packages/session/session-persistence-jsonl/src/format.ts` (`HeaderLine`: the first record is `{ type: 'session', ..., isSeeded: boolean, ... }`).

### Rules

`session-log-path.mjs`:

- The config block of the selected row is the row's lines after the line `  config:`, up to, not including, the first later row line that is not empty and has fewer than four leading spaces (or the row's end). A line is empty when it is empty or holds only spaces. Parsing rule 5 (root) and rule 6 (compression) search only the config block, instead of every later four-space line of the row.
- Nothing else changes: messages, order of checks, output.

`session-route.mjs`:

- After Reading step 6 finds the inherited prefix: when the first parsed event has `type === 'session'` and `isSeeded === true`, and step 6 found no tagged marker (count 0), print nothing to stdout, print `session-route: <LOG>: a seeded log has no inherited marker` to stderr, and exit 1. This check runs before step 7.
- A log whose header says `isSeeded: true` and has the marker is read as before. A log whose first event is not a `session` header, or whose header has `isSeeded` not `true`, is read as before.
- Nothing else changes.
