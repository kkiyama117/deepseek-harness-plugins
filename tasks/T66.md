### Rules

1. New module names in `bin/dispatch.py`:
   - `ACCEPT_MODES = ('off', 'shadow', 'enforce')`.
   - `REFUSED_EXIT = 7`.
   - `SHADOW_HEADER = 'utc\tcard\ttier\tverdict\texit\treasons\tcommits\told_land\taccept_json'`.
   - `utc_stamp()` returns `datetime.now(timezone.utc).strftime('%Y%m%dT%H%M%SZ')`. Rule 3 uses it; the other existing stamps stay as they are.
2. Mode. `_land` first reads `mode = os.environ.get('KSTACK_ACCEPT') or 'off'`. When `mode` is not in `ACCEPT_MODES`, it raises `DispatchError(f'KSTACK_ACCEPT must be off, shadow or enforce, not {mode}')` before anything else. With `off`, `land` behaves exactly as today: no check, no copy, no row. The default is `off`; this card sets no environment.
3. Accept steps (mode `shadow` or `enforce`), run right after the mode check and before every existing land step. `main = main_checkout(root)`, `agents = main / 'reports/agents'`, `evidence = evidence_dir(main, args.id)`, `utc = utc_stamp()`, `copy = None`.
   1. Run `[str(ACCEPT), 'check', str(agents), args.id]` with `capture_output=True, text=True`. Print its stdout to stdout exactly as given, and its stderr to stderr exactly as given. `exit` is its return code.
   2. When `exit` is 0 or 1: copy `evidence / 'accept.json'` with `shutil.copyfile` to `evidence / f'accept-{utc}.json'`, or, when that name exists, to the first free `accept-{utc}-{n}.json` for `n` = 2, 3, ...; `copy` is that path. Then read the copy as JSON: `commits` is `';'.join(f'{name}={commit}' for name, commit in record['commits'].items())`.
   3. When `exit` is negative (the check was killed by a signal), raise `ChildProcessError(f'kstack-accept check killed by signal {-exit}')`, which step 5 of this rule (3.5) handles, in both modes. When `exit` is 2 or any other positive value, there is no copy and `commits` is `''`.
   4. `verdict` is `'accept'` for exit 0, `'refuse'` for exit 1, and `'error'` otherwise. `reasons`: for exit 0 or 1, the first whitespace-separated word of every non-empty stdout line except the last non-empty line (the `ACCEPT` or `REFUSE` line), joined with `';'`; otherwise `''`.
   5. Any exception of type `Exception` raised in steps 1 to 4 (the check cannot start, the copy fails, the copy is not JSON or has no `commits` object) is an accept-step failure. Then `verdict = 'error'`, `exit = ''`, `reasons = f'exception:{type(error).__name__}'`, `commits = ''`, `copy = None` (a copy file already made stays on disk; section 8.2 keeps the row's `accept_json` empty for this cause), `step_error = error`, and the dispatcher prints `warning: kstack-accept step failed: {type(error).__name__}: {error}` on stderr.
   6. `tier` is the `tier` string of `evidence / 'scope.json'`, or `''` when that file cannot be read as a JSON object with a string `tier`.
4. Then the existing land steps run unchanged and in the same order: `issue_branch`, the worktree checks, the commit count, the ancestor check. A `DispatchError` from any of them sets `old_land = 'refused'`, writes the row (rule 6), and is raised again (exit 2, as today).
5. Enforce (mode `enforce` only), after the existing checks pass and before the fast-forward:
   1. When an accept step failed (rule 3.5): `old_land = 'refused'`, write the row, and raise `DispatchError(f'kstack-accept step failed: {type(step_error).__name__}: {step_error}')` (exit 2, as every dispatcher error; section 8.1).
   2. Otherwise, when `verdict` is not `'accept'`: `old_land = 'refused'`, write the row, print `land refused by kstack-accept (KSTACK_ACCEPT=enforce)` on stderr, and return `REFUSED_EXIT`.
   3. When `verdict` is `'accept'` but `git rev-parse card/<ID>` (in `root`) differs from `commits` of the copy for `LAND_REPO` (when `git rev-parse` itself fails, `old_land = 'refused'`, write the row, and raise its usual `DispatchError`, exit 2; the copy is read again from disk; a copy that cannot be read as JSON, has no `commits` object, or has no `LAND_REPO` key counts as different): `old_land = 'refused'`, write the row, print `card/<ID> moved after kstack-accept check; land refused` on stderr, and return `REFUSED_EXIT`.
   4. Before the fast-forward, open `agents / 'accept-shadow.tsv'` for append (UTF-8), writing `SHADOW_HEADER` first when the file is new or empty, and keep the open file for rule 6. Section 8.1 counts writing the row as an accept step, so in `enforce` an `OSError` here stops the land: print `warning: kstack-accept shadow row not written: {error}` on stderr and raise `DispatchError(f'kstack-accept shadow row not written: {error}')` (exit 2; no row can be written, and the land does not happen).
   In every refusal of this rule the worktree and `card/<ID>` stay, so the lead can fix and land again. In `shadow`, neither the verdict nor an accept-step failure stops the land.
6. The row. Each `land` call in `shadow` or `enforce` that gets past the mode check and `main_checkout` appends at most one row; when no row can be written, the stderr warning is the only record of that land, and the lead copies it into the report (section 8.2). It appends the row to `agents / 'accept-shadow.tsv'`, after `old_land` is known: `refused` (rule 4 or 5), `failed` (the fast-forward fails; the existing `DispatchError` is raised after the row), or `landed` (the fast-forward succeeded; the row is written before the worktree cleanup). The fields, tab-separated, in this order: `utc`, `args.id`, `tier`, `verdict`, `exit` (as a string), `reasons`, `commits`, `old_land`, and `str(copy)` when `copy` is a path, else `''`. When the file does not exist or is empty, write `SHADOW_HEADER` and a newline first. Each line ends with `'\n'`; append with mode `'a'`, UTF-8.
   When writing the row raises `OSError`: print `warning: kstack-accept shadow row not written: {error}` on stderr, then try once to append an error row with `verdict` `error`, `exit` `''`, `reasons` `exception:{type(error).__name__}`, `commits` `''`, `accept_json` `''` and the same `utc`, `card`, `tier` and `old_land`; if that fails too, print `warning: kstack-accept shadow row not written: {second error}` (the error of the second attempt) and continue. In `shadow`, and for a row written after a refusal, a row-write failure never changes the land's outcome or exit code. In `enforce`, the row of a land that reaches the fast-forward is written to the file opened in rule 5.4; when that write fails after the fast-forward has landed, the warnings above are printed and `land` still returns 0, because the land happened.
7. Module docstring: add this paragraph after the paragraph that starts `` `gate` refreshes the base``:

   ```text
   `land` reads KSTACK_ACCEPT: `off` (the default) lands as before; `shadow`
   runs `kstack-accept check` first, keeps accept-<UTC>.json beside the
   evidence, appends one row to reports/agents/accept-shadow.tsv, and lands
   whatever the verdict; `enforce` does the same but exits 7 without landing
   when the check does not accept or card/<ID> moved after it.
   ```
8. `AGENTS.md`, section `Card-flow adapter`, the `Dispatcher` bullet: right after the sentence that ends `` lines that `review` prints. ``, insert one space and the text inside the fence, which is one line; insert it on the bullet's own line, without the fence's indent. Change nothing else in `AGENTS.md`.

   ```text
   `land` runs `kstack-accept check` first when `KSTACK_ACCEPT` is `shadow` or `enforce` (default `off`) and appends one row to `reports/agents/accept-shadow.tsv`; in `enforce` a check that exits 1 or 2, or a `card/<ID>` that moved after it, stops the land with exit 7, and a failed accept step (the check cannot run, the copy cannot be made, or the log cannot be opened before the fast-forward) stops it with exit 2. Leads run `land` with `KSTACK_ACCEPT=shadow` until dsh-manager announces enforce. A lead never sets enforce.
   ```

### Tests

All in `bin/test_dispatch.py`, class `DispatchTest`, synthetic data in the test's temporary directory only; no test runs the real `kstack-accept`.

Helpers:
- `setUp` removes `KSTACK_ACCEPT` from the patched environment (`os.environ.pop('KSTACK_ACCEPT', None)`), so a test runs in `off` unless it sets a mode itself.
- `self.fake_check(exit, lines, commit=None, stderr='')` writes a new executable `self.base / 'kstack-accept-check'` and patches `dispatch.ACCEPT` with it for the rest of the test (`mock.patch.object`, stopped in cleanup). For `state` it behaves as `fake_accept` does. For `check` (`$1` is `check`, `$2` the agents dir, `$3` the card) it appends `check` to `self.record / 'checks.txt'`, prints each of `lines` on stdout, prints `stderr` on stderr when not empty, and, when `commit` is given, writes `"$2/evidence/$3/accept.json"` with `{"schema": "kstack-accept/result/1", "commits": {"deepseek-harness-plugins": "<commit>"}}`; then it exits with `exit`.
- `self.rows()` returns the lines of `self.root / 'reports/agents/accept-shadow.tsv'` split on `'\t'` (header first), or `[]` when the file does not exist.
- `self.ready_card()` runs `card T1 --no-worker`, commits a new file `bin/a.py` in the worktree, and returns `git rev-parse card/T1`.
- `self.copies()` returns the sorted names of `self.evidence` entries that match `accept-*.json`.
- A test sets the mode with `mock.patch.dict(os.environ, {'KSTACK_ACCEPT': ...})`.
