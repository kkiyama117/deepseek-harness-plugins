### 1. Tests never inherit the caller's git environment (do this first)

A test run inside a git hook, or by a caller that exported `GIT_INDEX_FILE`, `GIT_DIR`, or another `GIT_*` variable, must never touch that caller's repository or index.

- In `bin/test_dispatch.py` and in `bin/test_gate.py`, every `subprocess.run` of `git` that a test or a test helper makes (fixture setup, commits, asserts) passes `env=` a copy of `os.environ` from which every variable whose name starts with `GIT_` is removed. Put that copy in one module-level helper per file, `clean_git_env()`, which returns a new dict each call.
- Every call of `dispatch.main(...)` and `gate.main(...)` from a test runs inside `mock.patch.dict(os.environ, clean_git_env(), clear=True)`, so the code under test sees no caller `GIT_*` variable either. Tests that set a variable on purpose (`X` in `test_gate_env_does_not_override_the_caller`) add it inside that patch. `test_package_checks_do_not_get_the_index_copy` keeps its assert (`unset`), which the clean patch now makes reliable. The two `subprocess.run(['python3', 'bin/gate.py', ...])` calls of `test_script_exit_codes` also pass `env=clean_git_env()`.
- `bin/dispatch.py` and `bin/gate.py` do not change for this rule.

### 2. The gate rejects a `cwd` that is not a valid path

In `bin/gate.py`, `validate_check` raises `GateError(f'{package}: cwd is not a valid path')` when `cwd` contains a NUL character (`'\0'`), before it calls `resolve()`. Any `ValueError` or `OSError` from `resolve()` raises the same `GateError`.

### 3. The gate keeps file names byte for byte

In `bin/gate.py`, `run_git` returns `stdout` decoded from bytes with `os.fsdecode` (run `subprocess.run` without `text=True`; decode `stderr` with `errors='replace'`). So `-z` output keeps a carriage return or other byte inside a file name, and the names passed to `git add --intent-to-add` are the real names.

### 4. The dispatcher rejects a malformed card ID

In `bin/dispatch.py`, every verb checks each ID it is given against `^T[0-9]+$` before anything else (before `issue_branch`, `find_card`, or any sorting) and raises `DispatchError(f'not a card ID: {id}')` for the first one that does not match.

### 5. `test_land_refuses_main` checks that the worktree did not change

In `bin/test_dispatch.py`, `test_land_refuses_main` also asserts that, after the refused land, `git symbolic-ref --short HEAD` in the worktree still prints `card/T1`, its `git rev-parse HEAD` still equals the card commit, and its `git status --porcelain` is still empty.
