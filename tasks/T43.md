### Rules

1. **Lexical paths, like Core.** Every path option (`--dsh-home`, `--target`, `--source`, `--record`, `--run-worker`, and `--dsh` when it contains `/`) is made absolute and normalized lexically: `Path(os.path.normpath(os.path.abspath(os.path.expanduser(value))))`. `..` is removed by text, not by following symlinks, as Core's `path.resolve` does for the home. Core's `expandHomePath` expands only `~`, `~/`, and `~\`, while Python's `expanduser` also expands `~user`; so a `--dsh-home` or `$DSH_HOME` value that starts with `~` but is neither `~` nor starts with `~/` is a usage error: `LIVE_APPLY_USAGE: the harness home must not use ~user or ~\: <value>`, exit 2. This replaces T40's `Path(value).expanduser().absolute()`. Usage messages print these normalized paths. The default home (`$DSH_HOME` or `~/.dsh`) is normalized the same way.

   Core resolves the home by text, `run-worker.sh` by following symlinks, and the file system by following symlinks then `..`. So that all three name the same directory, the first usage rule after T40's blank-`--dsh-home` rule is: if `os.path.realpath(<lexical home>) != os.path.realpath(os.path.expanduser(<home as given>))`, print `LIVE_APPLY_USAGE: the harness home names different directories by text and by the file system: <lexical home>` and exit 2. The same test applies to `--target` right after T41's `target is a symlink` rule (so a symlinked target reports that first), with the message `LIVE_APPLY_USAGE: the target names different files by text and by the file system: <lexical target>`.

2. **No symlinked patch or profile directory in the home.** New usage rules for both routes, right after T41's three symlink rules, checking in this order and stopping at the first hit: `os.path.islink(H / 'cordis.patch.yml')`; then `os.path.islink(H / 'profiles')`; then, only when `H / 'profiles'` is a directory, for each entry `<name>` of it in sorted order, `os.path.islink(H / 'profiles' / <name>)` and then, when that entry is a directory, `os.path.islink(H / 'profiles' / <name> / 'cordis.patch.yml')`. A hit prints `LIVE_APPLY_USAGE: a patch or profile directory in the harness home is a symlink: <path>` and exits 2. When `H / 'profiles'` is not a directory the scan is skipped, so T40's `probe profile headless does not exist` message still applies. A link elsewhere could make one patch change another.

   Also, after T41's realpath record rule and before T40's rule 7 (`record directory is not empty`): if `os.path.islink(RECORD)`, print `LIVE_APPLY_USAGE: record directory is a symlink: <RECORD>` and exit 2, before any `mkdir` or `chmod`.

3. **Directory descriptors.** After the usage rules pass, open the target's directory without following symlinks and keep it open until the script exits:
   - Both routes: `home_fd = os.open(H, os.O_RDONLY | os.O_DIRECTORY)` (a symlink at `H` itself or above it stays allowed, as T41 says).
   - `home-patch`: `dir_fd` is `home_fd` (the same descriptor).
   - `profile-patch`: then `profiles_fd = os.open('profiles', os.O_RDONLY | os.O_DIRECTORY | os.O_NOFOLLOW, dir_fd=home_fd)`, then `dir_fd = os.open(<name>, os.O_RDONLY | os.O_DIRECTORY | os.O_NOFOLLOW, dir_fd=profiles_fd)`; close `profiles_fd` after; keep `home_fd` for rule 4.
   - An `OSError` here (including `ELOOP` when a component was replaced by a symlink after the check) prints `live-apply: open target directory: <error>` and exits 2 with nothing on stdout; nothing has been written. This exit, and rule 4's two exits, count as usage errors: like T40's usage errors they print no summary.
   - From then on every access to the target goes through `dir_fd` with the bare file name `T.name`: reading the old target (`os.open(T.name, os.O_RDONLY | os.O_NOFOLLOW, dir_fd=dir_fd)`, then `os.fstat` for the mode), the temporary file (`os.unlink(tmp_name, dir_fd=dir_fd)` with `FileNotFoundError` ignored, `os.open(tmp_name, O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW, mode, dir_fd=dir_fd)`), `os.replace(tmp_name, T.name, src_dir_fd=dir_fd, dst_dir_fd=dir_fd)`, the restore (the same calls, or `os.unlink(T.name, dir_fd=dir_fd)` when the old target was absent, ignoring `FileNotFoundError`), the existence test (`os.stat(T.name, dir_fd=dir_fd, follow_symlinks=False)`), and every removal of the temporary file (after a failure, and T41's interrupt cleanup). `tmp_name` is `'.' + T.name + '.live-apply-tmp'`. So a directory swapped after the check is never written; the write goes to the directory that was checked.

4. **One run per home.** Keep `home_fd` (rule 3) open for both routes and, right after opening the descriptors, take `fcntl.flock(home_fd, fcntl.LOCK_EX | fcntl.LOCK_NB)`, so a home-patch run and a profile-patch run on the same home never overlap. On `BlockingIOError`, print `LIVE_APPLY_USAGE: another live-apply run holds <H>` and exit 2 with nothing on stdout; any other `OSError` from `flock` prints `live-apply: lock harness home: <error>` and exits 2 with nothing on stdout. The lock is released when the script exits.

5. **Record files through a descriptor.** After step 4's `mkdir` and `chmod`, open `record_fd = os.open(RECORD, os.O_RDONLY | os.O_DIRECTORY | os.O_NOFOLLOW)`; an `OSError` is `write record`. Every file the script writes in the record (`source.yml`, `backup.yml` or `backup-absent`, each `.out`/`.err`, `summary.json`) is created with `os.open(<name>, os.O_WRONLY | os.O_CREAT | os.O_EXCL | os.O_NOFOLLOW, 0o600, dir_fd=record_fd)`, written completely (looping on `os.write`), and `os.fchmod`ed to `0o600`. Because the record started empty and every name is written once, `O_EXCL` never meets a file of its own; an existing name (for example a symlink someone inserted) fails as `write record` (or `write summary` for `summary.json`). `summary.json` is written only through `record_fd`: when `record_fd` was never opened, no `summary.json` is written and the summary's `record` is `null`; otherwise `record` is `str(RECORD)`, even if the path was swapped afterwards.

6. **No leftover processes in the group.** In `run_child`, after `communicate` returns normally, kill the process group too (`os.killpg(proc.pid, signal.SIGKILL)`, ignoring `ProcessLookupError`), so a grandchild left in the group with closed pipes does not outlive the check. A process that leaves the group (for example with `setsid`) is out of scope.

7. **Upper bounds for the waits.** `retry_seconds` also rejects a value greater than `3600`, and `probe_timeout_seconds` a value greater than `86400`. Every rejection of each option now uses one message: `must be a finite number of seconds, at least 0 and at most 3600` for `--retry-delay`, and `must be a finite number of seconds, greater than 0 and at most 86400` for `--probe-timeout`. So `time.sleep` and `communicate` never get a value that overflows.
