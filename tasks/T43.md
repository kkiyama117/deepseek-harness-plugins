### Rules

1. **Paths by text, like Core.** Finding: a home given with a symlink and `..` made the script change one directory while DSH checked another. Every path option (`--dsh-home`, `--target`, `--source`, `--record`, `--run-worker`, and `--dsh` when it contains `/`), a home taken from `$DSH_HOME`, and the default home are normalized by text (a given home is first stripped with `strip()`): `Path(os.path.normpath(os.path.abspath(os.path.expanduser(value))))`. This replaces T40's `Path(value).expanduser().absolute()`. Messages that print a path print this normalized path, except where a rule below says "raw".

2. **No `~user` home.** Python's `expanduser` expands `~user`, Core does not. The "home value" is the text of `--dsh-home` when it is given, otherwise `$DSH_HOME` when it is set and not blank, each after `strip()`; otherwise there is no home value (the default `~/.dsh` is fine). If the home value starts with `~` and is neither `~` nor starts with `~/`, print `LIVE_APPLY_USAGE: the harness home must not use ~user or ~\: <home value>`, where `<home value>` is the stripped text, not normalized (raw). A home starting with `~\` is rejected on purpose too: Core expands it but Python does not. This rule runs right after T40's blank-`--dsh-home` rule.

3. **Text and file system must agree.** Core resolves the home by text, `run-worker.sh` and the file system by following symlinks. So that they name the same place, compare `os.path.realpath(<normalized path>)` with `os.path.realpath(os.path.expanduser(<raw path>))`, where the raw path of a given home is its stripped home value (rule 2), and of the default home is `~/.dsh`:
   - Home, right after rule 2: on a difference, `LIVE_APPLY_USAGE: the harness home names different directories by text and by the file system: <normalized home>`.
   - Target, right after all three of T41's symlink rules (so their messages win) and before rule 4: `LIVE_APPLY_USAGE: the target names different files by text and by the file system: <normalized target>`.
   - Record, right after rule 5: `LIVE_APPLY_USAGE: the record names different directories by text and by the file system: <normalized record>`.

4. **No symlinked patch or profile directory in the home.** Finding: a home patch that was a symlink to the web patch let a web run change every production profile. Right after rule 3's target check (T41's symlink rules and the target check win where they apply), check in this order and stop at the first hit: `os.path.islink(H / 'cordis.patch.yml')`; `os.path.islink(H / 'profiles')`; then, only when `H / 'profiles'` is a directory, for each entry `<name>` of `os.listdir(H / 'profiles')` in sorted order, `os.path.islink(H / 'profiles' / <name>)`, and, when that entry is a directory, `os.path.islink(H / 'profiles' / <name> / 'cordis.patch.yml')`. A hit prints `LIVE_APPLY_USAGE: a patch or profile directory in the harness home is a symlink: <path of the hit>`. When `H / 'profiles'` is not a directory the scan stops after the second test, so T40's `probe profile headless does not exist` message still applies later.

5. **No symlinked record.** Finding: a `--record` symlink outside the home passed T41's real-path rule, and `mkdir`/`chmod` then changed the directory it pointed to. Right after T41's real-path record rule and before T40's `record directory is not empty` rule: if `os.path.islink(RECORD)`, print `LIVE_APPLY_USAGE: record directory is a symlink: <normalized record>`.
