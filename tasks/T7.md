A security review of pull request #58 found four ways for private data or the caller's repository to be reached. Change only what the rules below say; keep every other name, message, and test as it is, except the tests this card names.

### 1. The dispatcher never inherits the caller's git environment

- Add `clean_env()` to `bin/dispatch.py`: a copy of `os.environ` without any variable whose name starts with `GIT_`.
- `git()` runs with `env=clean_env()`. So do the gate run of `review` (`run_gate`) and the worker command in `run_worker`.
- `run_worker` passes the brief with `encoding='utf-8', errors='surrogateescape'`, so a diff or file name that is not UTF-8 reaches the worker byte for byte instead of raising.

### 2. `git()` keeps file names byte for byte

- `git()` runs `subprocess.run` without `text=True` and returns a `subprocess.CompletedProcess` whose `stdout` is `os.fsdecode(<bytes>)` and whose `stderr` is decoded as UTF-8 with `errors='replace'`, as in `bin/gate.py`. Its `returncode`, `allow_failure`, and the `DispatchError` message stay as they are.

### 3. The gate never passes the caller's git environment on

- Add `clean_env()` to `bin/gate.py`, the same as rule 1.
- `check_env(check)` starts from `clean_env()` instead of `os.environ`, then adds each `env` entry that is not already set. A package check therefore never sees a caller's `GIT_INDEX_FILE` (this replaces T2's "a `GIT_INDEX_FILE` that the caller exported passes through unchanged").
- The gate's own git commands and the document checks start from `clean_env()` too, and then add the index-copy variables as now.

### 4. The reviewer's brief carries no output of code the worker wrote

- `run_gate` now also prints the gate's merged stdout and stderr (decoded with `errors='replace'`, as now) to the lead's stdout right after its `gate exit <n>` line: nothing when the output is empty, else the output verbatim (`print(output, end='')`), followed by one `print()` only when the output does not already end with a newline.
- The `gate_tail` it returns is one line that the dispatcher formats itself: `f'gate: PASS ({n} checks)'`, with `n` the integer parsed from the output's last non-empty line, when the exit code is 0 and that line matches `^gate: PASS \(([0-9]+) checks\)$` exactly; else `gate: FAIL`. No other text the worktree's code printed reaches the brief. Every `gate: <key>: ...` line, `gate: FAIL: ...` list, and any other line stays on the lead's stdout only.
- `GATE_BLOCK` says `The dispatcher ran \`python3 bin/gate.py\` before you started; it exited {gate_code}. Its result (the output of the checks is not shown to you):` in place of `The last lines of its output:`.
- In the review briefs, `untracked` lists only untracked paths that are not symlinks. For each untracked symlink, print `untracked symlink not shown to the reviewer: <absolute path> -> <target>` to stdout instead, before the gate runs, in `git ls-files` order (an unreadable one in its place), where `<target>` is the raw `os.readlink` value, or `(unreadable)` when it raises `OSError`. Both `review` and `review --main` do this, and the filter runs before `review --main`'s `no changes in the given paths` check, so an untracked symlink alone is no change.
