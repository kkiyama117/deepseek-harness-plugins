## T2. Repository gate

Issue: #47.

Needs: T1.

Spec: `AGENTS.md` sections "Rules for card implementers" and "Card-flow adapter" (the Gate item); `tasks/README.md`. This card states the whole behavior.

Files: `bin/gate.py`, `bin/gate-checks.json`, `bin/test_gate.py`.

One command, `python3 bin/gate.py [--base REF]`, that runs the checks of every package changed since `REF` (default `origin/main`) and the document checks, and exits 0 only when all of them pass. Python standard library only. Expose `main(argv=None, root=ROOT)`, which sets `root = Path(root).resolve()` first and returns the exit code (`argv=None` means `sys.argv[1:]`; parse with `argparse`, whose own usage errors exit 2 by raising `SystemExit`, untested), `package_of(path)`, and `load_checks(root)`, which reads and validates `root/bin/gate-checks.json`, returns the dict exactly as parsed (no keys filled in), and raises `GateError(reason)` on any problem; with `ROOT = Path(__file__).resolve().parents[1]`; every git command and check runs against `root`.

### Changed paths

1. `base` is `git merge-base <REF> HEAD` in `root`. When it fails, print `gate: cannot find the merge base of <REF> and HEAD` to stderr and return 2.
2. Never write the real index. Copy the file named by `git rev-parse --path-format=absolute --git-path index` into a `tempfile.TemporaryDirectory()` with the default location (never under `root`), and run every later git command and every document check with `GIT_INDEX_FILE` set to that copy. Also create the directory `objects` in that temporary directory, and set `GIT_OBJECT_DIRECTORY` to it and `GIT_ALTERNATE_OBJECT_DIRECTORIES` to the real object store (`git rev-parse --path-format=absolute --git-path objects`) in the same environment, so that the gate never writes the real object store; a worker's sandbox mounts it read-only. (`git add --intent-to-add` writes the empty blob; without the temporary directory it exits 128 on a read-only store, which is what stopped the first worker run.) In that environment, run `git add --intent-to-add -- <paths>` for the paths from `git ls-files --others --exclude-standard -z` (skip the command when there are none), so that new untracked files count as changed, so that `bin/check-layout-links.py` also checks the links of new Markdown files (intended), and so that `git diff --check <base>` in step 2 of Run also checks their whitespace (this is the whitespace check that `tasks/README.md` asks for).
3. The changed paths are `git diff --name-only --no-renames -z <base>` in that environment. Deleted paths count.
4. When any git command of steps 2 and 3 fails, print `gate: git failed: <command>: <stderr>` to stderr and return 2.

All other `gate:` lines, and the output of the checks, go to stdout. Flush stdout after every `gate:` line, so each label appears before the output of its command. `<command>` is the git argv joined by spaces and `<stderr>` is stripped; `GateError` takes one string, and its reason texts are free.

### Packages

`package_of(path)` maps one changed path (POSIX, relative to the root) to a package key, or `None`, from the path string alone (deleted paths do not exist on disk; "directory" below means a part before the last `/`). Apply the rules top to bottom; the first match wins, so a `.md` file inside a package maps to `None`:

- A path that ends in `.md` → `None` (the document checks cover it).
- `plugins/dsh-web-ui/packages/<x>/...` with at least one more part after `<x>` → `plugins/dsh-web-ui/packages/<x>`.
- `plugins/<x>/...`, `presets/<x>/...`, `configs/<x>/...`, `skills/<x>/...` with at least one more part after `<x>` → that two-part prefix.
- Any other path with a directory → its first part (for example `bin`, `tests`, `.github`, or `plugins` for a file directly under `plugins/`).
- A file at the root → `.`.

So `plugins/dsh-web-ui/packages/index.json` maps to `plugins/dsh-web-ui`.

### Checks file

`bin/gate-checks.json` is one JSON object: package key → non-empty list of checks. A check is an object with exactly the keys `cwd` (string, a directory relative to the root), `run` (string, a shell command), and optionally `env` (object of string to string). Anything else makes `load_checks` raise: a missing or unreadable file, invalid JSON, a value that is not an object, an empty list, an unknown or missing key, a non-string value, or an empty or whitespace-only `run`, an `env` that is not an object or holds a non-string value, or a `cwd` that is not an existing directory inside the root after `resolve()` (the root itself, `cwd` `.`, counts as inside). `main` then prints `gate: invalid bin/gate-checks.json: <reason>` to stderr and returns 2. The top-level value must be an object (`{}` is valid), each package value a list, and each check an object. `cwd` must be a relative path (not absolute) whose `resolve()` against the root stays inside the root; `plugins/../bin` is allowed. `main` loads the file first, before the merge base and before any check.

A package check runs with a copy of `os.environ` (so `PATH` is inherited), plus each `env` entry that the caller's environment does not already have. It does not get the index copy's `GIT_INDEX_FILE`; a `GIT_INDEX_FILE` that the caller exported passes through unchanged. A command that cannot start fails through the shell's exit code (for example 127) and is reported like any other failure.

### Run

1. For each changed package key, sorted, deduplicated: when the key has no entry and its directory no longer exists under the root (the card deleted the package), print `gate: <key>: deleted` and go on; this is not a failure and runs nothing. Otherwise, when the key has no entry, print `gate: <key>: no checks defined; add them to bin/gate-checks.json` and count it as a failure. Otherwise run each of its checks in order, all of them even after one fails, with `subprocess.run(run, shell=True, cwd=root / cwd, env=...)`, output passed through. Print `gate: <key>: <run>` before and `gate: <key>: ok` or `gate: <key>: FAIL (exit <n>)` after. Go on with the next package after a failure.
2. Always run the document checks last, from the root, with a copy of `os.environ` in which `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` are the values of Changed paths step 2 (replacing any value the caller had), as argument lists without a shell: `['python3', 'bin/check-layout-links.py']`, then `['git', 'diff', '--check', <base SHA>]`. Their labels are `python3 bin/check-layout-links.py` and `git diff --check`. Their stdout and stderr pass through, as for package checks, between the two `gate: docs:` lines. Print `gate: docs: <label>` before and `gate: docs: ok` or `gate: docs: FAIL (exit <n>)` after.
3. The last line is `gate: PASS (<n> checks)`, where `<n>` counts every check and document check that ran, and the return value is 0; or `gate: FAIL: <failed items joined by ", ">`, and the return value is 1. There is one item per failed check, in the order the keys were processed (a key without checks takes its sorted position; it is not counted in `<n>`): `<key>: <run>` for a failed package check, `<key>` for a package without checks, and `docs: <label>` for a failed document check.

Test rules: `bin/test_gate.py` puts its own directory on `sys.path` and runs `import gate`, as `bin/test_dispatch.py` does. `unittest`, every test in a `tempfile.TemporaryDirectory` holding a temp repository (`git init -b main`, every git command with `-c user.name=test -c user.email=test@example.invalid -c commit.gpgsign=false`). Tests that depend on the caller's environment set it with `mock.patch.dict(os.environ, ...)` and remove `X` and `GIT_INDEX_FILE` from it when they need them absent. Checks in the tests are plain shell commands such as `true`, `exit 3`, or `touch marker`. Never run the real checks, never use the network.
